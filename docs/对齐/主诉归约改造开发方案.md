# 主诉归约改造开发方案（可直接开发）

> 上位设计：`docs/对齐/主诉归约全链路企业级方案.md`。两边冲突时以本文为准（主要是 N1 模型失败的兜底、N4 失败后 N6 的兜底、允许列表范围）。
> 不变的约束：状态 1–8 不变；URGENT 终态不解锁；DRAFT 不提 BASELINE；急症目录 classpath 不热更；D-15 不变；跟踪的 yml 不放真实密钥；不依赖老 HIS 运行时。

---

## 0. 一页结论

| 节点 | 规则层（能定就定） | 模型层（规则定不了才调） | 兜底层（模型也定不了） |
|---|---|---|---|
| N1 安全 | 急症/转人工/不适宜命中即钉死；**未命中风险触发词 → 判定无风险，不调模型** | 命中风险触发词、影子命中或规则不确定 → `SignalExtractor` | **安全降级 `SAFE_FALLBACK`（停）**，不是继续导诊 |
| N2 含糊 | 有症状/归约词/槽位 → 不含糊；笼统词且短 → 含糊 | 无 | 追问一次，第二次放行 |
| N3 槽位 | `SlotParser` / 就诊人 | 无 | 缺什么问什么 |
| N4 归约 | 病名字面；已审同义规则；只含非歧义症状；不确定话术 | 只剩歧义症状、或有话但目录全不中 | `terms=[]` 且标 `canonResolved=false` |
| N5 抽症状 | 目录 ROUTING 最长匹配 | 无 | 空列表 |
| N6 挂科 | 患者确认 > 不确定话术 > OVERRIDE > 儿科 > 病种 > 单一专科症状 > 同一级科最早 | 跨一级冲突、只有歧义症状、全不中 | **全科**（不再用孤立症状词挂专科） |
| N7 卡片 | 患者确认/改科最高优先 | 无 | 保持当前卡 |
| N8 派医生 | 归约词精确命中擅长 > 原话命中擅长 > 本科最空 > 一级最空 | 无 | 全科；都没有 1305 |
| N9 占坑 | occupy 成功 | 无 | 换下一位，穷尽 1305（**单独工作流：释放**） |

- N4 与 N6 合用**一次**模型调用（`ComplaintModel`），一个回复分两个字段，各自校验、各自记账。
- 支付路径（`placeOrder` → 派医生）**0 次模型调用**，只读出卡时持久化的 `triage`。
- 去掉两个产品开关：`safety.model.enabled`、`inquiry.advisor-enabled`。缺密钥时由模型网关回报不可用，按各节点兜底走。
- 每个节点每次运行写一行 `consult_match_decision`（N1 继续写 `safety_decision_audit`，补两列）。

## 1. 现状与改动点对照

| 现状（代码位置） | 问题 | 改动 |
|---|---|---|
| `SafetyGate.assess` 规则没判急症就**每条消息**调模型 | 常开后成本高；模型失败直接 `SAFE_FALLBACK`，可用性随模型抖动 | 加 `ModelTriggerScan`：未触发=规则明确无风险，`SKIPPED` |
| `SafetyConfiguration.signalExtractor` 按 `enabled` 选空实现 | 产品开关 | 删开关，总是 `DeepSeekSignalExtractor`（经 `ModelGateway`） |
| `RegistrationAgent.needsAdvisor` = `fast.evidence()==null` | 「头晕」能命中神经内科，模型永远不调；高血压症状挂错 | 换成 `TriageEngine`，按 N4/N6 的不确定判定调模型 |
| `DepartmentRouter.firstRouting` 谁先出现跟谁 | 不分病名/症状/既往史；跨一级冲突也硬选 | 新增 `route(RouteInput)`，返回带 `certainty` 的决定 |
| `DepartmentSpecialty.routingKeywords` 病名和症状混在一起 | 无法做「病种优先」 | 目录新增 `DISEASE` 词型、歧义症状表、同义规则表 |
| `DoctorAssigner.assign(card)` 只传描述+症状 | 擅长只能字面匹配 | 传 `canonicalTerms`；`DoctorMatcher` 精确命中加权；回 `matchSource` |
| `DeepSeekDepartmentAdvisor` / `DeepSeekSignalExtractor` 各自建 HttpClient、各自限流 | 无熔断、无缓存、无统一超时 | 抽 `ModelGateway` |
| 无节点级记账 | 无法按步优化 | `consult_match_decision` + Micrometer 指标 + 分层抽样标注 |
| `in_flight` 只加不减 | 医生 3/3 后派不出 | 第 6 阶段单独做释放 |

### 2.2 N1 安全：何时调模型

新文件 `src/main/resources/safety/model-triggers.json`（与急症目录分开，不改 BASELINE）：

```json
{
  "version": "2026.10.23",
  "triggers": [
    {"id": "T-CHEST",   "all": [["胸", "心口", "心窝"], ["压", "闷", "紧", "痛", "疼", "揪", "堵"]]},
    {"id": "T-BREATH",  "all": [["喘不上", "憋气", "上不来气", "透不过气", "憋得慌"]]},
    {"id": "T-NEURO",   "all": [["半边", "一侧", "嘴歪", "口角", "说话不清", "舌头不利索"]]},
    {"id": "T-FAINT",   "all": [["晕倒", "昏过去", "叫不醒", "意识不清", "抽搐", "抽筋"]]},
    {"id": "T-BLEED",   "all": [["吐血", "咯血", "便血", "黑便", "大出血", "止不住血"]]},
    {"id": "T-PREG",    "all": [["怀孕", "孕"], ["出血", "流血", "肚子疼", "腹痛"]]},
    {"id": "T-SELF",    "all": [["不想活", "想死", "自杀", "轻生", "吃了一瓶", "吃了很多药"]]},
    {"id": "T-CHILD",   "all": [["孩子", "宝宝", "小孩", "婴儿"], ["高烧", "烧到39", "烧到40", "精神差", "不吃奶"]]}
  ]

```

- `all` 是组的数组，**每组至少命中一个词**才算触发；匹配用 `CompactText.of(原话)`（与急症闸门一致，不用 `SpokenNormalizer`）。
- 初版词表需临床复核后才上线；改词表=发版。

`SafetyGate.assess` 新流程：

```
rules = engine.evaluate(...)
if rules.urgent → SKIPPED（不变）
triggers = triggerScan.scan(transcript)                  // List<String> 触发编号
needModel = !triggers.isEmpty() || rules.undetermined() || !rules.shadowRuleIds().isEmpty()
if !needModel → withModelStatus(rules, SKIPPED)，certainty=CERTAIN   // 规则明确：无风险
extraction = extractor.extract(...)
if extraction 非 SUCCESS → fallbackFromModel(...)        // 已有：undetermined=true → SAFE_FALLBACK
...其余不变（union，模型不能否掉急症）
```

- **规则 CERTAIN 的定义**：已判急症/转人工/不适宜；或未命中任何触发词、无影子命中、规则未标不确定。
- **模型失败的兜底**：只发生在「已触发」的会话上，走 `SAFE_FALLBACK`（现有模板）。`undetermined` 不锁存，患者下一句会重评，所以不是死锁。
- `SafetyAssessment` 增加 `List<String> modelTriggerIds`；`safety_decision_audit` 增加两列（§5.1）。

### 2.3 N4 归约 `ComplaintCanon.rule(...)`

输入：`description` 原文 `raw`，`text = SpokenNormalizer.forMatch(raw, snapshot)`。
产出：

```java
public record CanonResult(
        List<CanonTerm> terms,          // 当前主诉的标准病种，≤2
        List<CanonTerm> historyTerms,   // 既往史里的病名，只记录，不参与挂科
        List<SymptomHit> symptoms,      // 目录症状命中，带是否歧义、所属二级
        List<String> shadowRuleIds,     // DRAFT 同义规则命中
        Certainty certainty,
        DecisionSource source,
        String reason,
        boolean resolved) {}            // false = 不确定且模型也没给出 → N6 不能信孤立症状

public record CanonTerm(String term, String ruleId, Span evidence) {}  // ruleId: LITERAL / 同义规则编号 / MODEL
public record SymptomHit(String phrase, boolean ambiguous, int departmentCode, String specialty, Span evidence) {}
```

判定顺序（第一条命中即返回）：

| # | 条件 | certainty | terms | reason |
|---|---|---|---|---|
| 1 | `text` 为空 | CERTAIN | [] | `EMPTY` |
| 2 | 命中不确定话术 | CERTAIN | [] | `UNCERTAIN_MARKER` |
| 3 | 命中 DISEASE 词且不在既往史语境 | CERTAIN | 字面病名 | `DISEASE_LITERAL` |
| 4 | 命中 REVIEWED 同义规则 | CERTAIN | 规则目标病名 | `SYNONYM` |
| 5 | 有非歧义症状命中 | CERTAIN | [] | `SYMPTOM_ONLY` |
| 6 | 只有歧义症状命中 | UNCERTAIN | [] | `AMBIGUOUS_ONLY` |
| 7 | 全不中且 `text.length() >= 6` | UNCERTAIN | [] | `NO_HIT` |
| 8 | 全不中且很短 | CERTAIN | [] | `TOO_SHORT` |

- DISEASE 扫描与 `SymptomExtractor` 相同：从左到右、最长匹配、不重叠。
- **既往史语境**（命中则放 `historyTerms`）：
  - 前置：`(既往|以前|曾经|之前|老毛病|一直有)[^，。；,]{0,6}$TERM`
  - 后置：`$TERM[^，。；,]{0,3}(病史|多年|好几年|十几年|吃药控制)`
- 第 3、4 条同时命中时合并去重，按证据位置排序，最多 2 个。
- DRAFT 同义规则只记 `shadowRuleIds`，不进 `terms`。

### 2.4 N6 挂科 `DepartmentRouter.route(RouteInput)`

```java
public record RouteInput(String description, CanonResult canon, Integer age, Gender gender) {}
public record RouteDecision(
        DepartmentRouter.Advice advice,
        Certainty certainty,
        DecisionSource source,
        String reason,
        List<String> candidates) {}       // 不确定时交给模型的候选二级科
```

判定顺序：

| # | 条件 | 结果 | certainty | reason |
|---|---|---|---|---|
| 1 | 空 / 不确定话术 | 全科 | CERTAIN | `UNCERTAIN_MARKER` |
| 2 | OVERRIDE（中医） | 该科；内部优先用病种所属二级映射，否则沿用现有 ROUTING | CERTAIN | `OVERRIDE` |
| 3 | 儿科拦截 | 儿科；成人二级优先取病种的二级，再走 `mapToPediatric` | CERTAIN | `PEDIATRIC` |
| 4 | `canon.terms` 非空，性别过滤后只落一个二级，且没有非歧义症状落在**其他一级** | 病种二级 | CERTAIN | `CANON_TERM` |
| 5 | `canon.terms` 落多个二级，或病种与非歧义症状跨一级 | — | UNCERTAIN | `CONFLICT`，候选=涉及的二级 + 全科 |
| 6 | 无病种；非歧义症状只落一个二级 | 该二级 | CERTAIN | `SINGLE_SPECIALTY` |
| 7 | 无病种；非歧义症状落多个二级，但都在同一一级 | 最早出现者（沿用 `consider`） | CERTAIN | `SAME_L1_EARLIEST` |
| 8 | 无病种；非歧义症状跨一级 | — | UNCERTAIN | `CONFLICT` |
| 9 | 只剩歧义症状 / 全不中且 N4 判不确定 | — | UNCERTAIN | `AMBIGUOUS_ONLY` / `NO_HIT`，候选=全部已开通二级 |
| 10 | 全不中且 N4 判 `TOO_SHORT` | 全科 | CERTAIN | `NO_HIT_SHORT` |

- 病种的性别范围不符时，该病种不参与第 4/5 条（reason 附 `GENDER_SKIP`）。
- 旧的 `advise(description, age, gender)` 保留，内部改为 `route(...)`，不确定时直接全科。旧单测和管理端预览继续能用。

### 2.5 合并：一次模型调用，两段记账

`TriageEngine.run(TriageInput)`（新，domain 层，无 Spring 依赖）：

```
canonRule = canon.rule(raw, snapshot)
routeRule = router.route(new RouteInput(raw, canonRule, age, gender))
routeFixed = routeRule.reason ∈ {UNCERTAIN_MARKER, OVERRIDE}      // 科室已被话术/中医钉死
reply     = (routeRule.UNCERTAIN || (canonRule.UNCERTAIN && !routeFixed))
              ? complaintModel.interpret(raw, age, gender, allowTerms, routeRule.candidates)
              : ComplaintReply.notCalled()

N4 最终：
  canonRule.CERTAIN              → canonRule（source=RULE）
  canonRule.UNCERTAIN 且 routeFixed → terms=[]，source=RULE，reason=SKIPPED_BY_ROUTE，resolved=true
  reply.SUCCESS                  → terms = 校验后的 reply.terms（source=MODEL；空则 reason=MODEL_NONE），resolved=true
  其他                            → terms=[]，source=FALLBACK，reason=MODEL_<status>，resolved=false

N6 最终：
  routeRule.CERTAIN              → routeRule
  N4 最终 source=MODEL 且 terms 非空
      → again = router.route(用模型 terms 重算)；again.CERTAIN → again，source=MODEL，reason=MODEL_TERM_ROUTED
  reply.SUCCESS 且 reply.specialty ∈ candidates 且证据是原话子串
      → 该二级，source=MODEL，reason=MODEL_PICK
  其他                            → 全科，source=FALLBACK，reason=MODEL_<status> | MODEL_OUT_OF_CANDIDATES
```

要点：

- **N4 失败时 N6 不信孤立症状**：第 9 条本来就是 UNCERTAIN，模型失败只能落全科，不会退回到「头晕→神经内科」。
- 「规则路由模型输出」：模型给了病种，挂科仍由目录规则映射，结果可复现、可解释。
- **允许列表**：`allowTerms` = 快照里已开通二级科的 DISEASE 词，仅此一处来源。同义规则的目标在写入时就必须是 DISEASE 词（§3.3）。医生擅长**不进**允许列表，只给 N8 打分用。
- 模型回复校验失败（不在允许列表 / 证据不是子串 / 超过 2 个）：整段字段丢弃，按 `MODEL_INVALID` 走兜底，不部分采纳。

### 2.6 N2 含糊（只改一处）

`ComplaintClarity.isVague` 多加一条：`canon.rule(text)` 命中 DISEASE 或同义规则 → 不含糊。其余不变。

### 2.7 N8 派医生打分

`DoctorMatcher.pick(all, specialty, departmentCode, text, canonTerms)`：

| 命中方式 | 分值 | `MatchSource` |
|---|---|---|
| 擅长切词与某个 `canonTerm` **完全相等** | `1000 + term.length()` | `SKILL_CANON` |
| 擅长切词是 haystack 的子串（现有逻辑） | `term.length()` | `SKILL_TEXT` |
| 本二级无命中，挑最空 | 0 | `LOAD_L2` |
| 本一级无命中，挑最空 | 0 | `LOAD_L1` |
| 全科 | 0 | `GENERAL` |

- 先在二级里比，再在一级里比，顺序不变；同分时 `inFlight` 少者优先，再看 `remainNum` 多者。
- `Pick` 增加 `MatchSource source`；`AssignDoctorRes` 增加 `String matchSource`。

### 3.3 同义归约规则表

```sql
CREATE TABLE IF NOT EXISTS consult_canon_synonym (
    rule_id       VARCHAR(32)  NOT NULL COMMENT '规则编号，例如 SYN-HTN-001',
    target_term   VARCHAR(32)  NOT NULL COMMENT '归约到的标准病名，必须是目录 DISEASE 词',
    all_groups    JSON         NOT NULL COMMENT '[[a,b],[c]]：每组至少命中一个，所有组都命中才算',
    none_terms    JSON         NOT NULL COMMENT '出现任一即不命中，例如否定词「没有」「不」紧邻',
    pattern       VARCHAR(128) NULL     COMMENT '可选正则，与 all_groups 同时满足。只允许数值类，如 血压(1[4-9]\\d|2\\d\\d)',
    status        TINYINT      NOT NULL DEFAULT 1 COMMENT '1DRAFT只记影子 2REVIEWED参与决策 3RETIRED',
    reviewer      VARCHAR(64)  NULL     COMMENT '临床审核人',
    reviewed_at   DATETIME(3)  NULL     COMMENT '审核时间',
    remark        VARCHAR(400) NULL     COMMENT '备注',
    created_by    VARCHAR(100) NULL     COMMENT '创建人',
    updated_by    VARCHAR(100) NULL     COMMENT '修改人',
    created_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
    updated_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '更新时间',
    is_deleted    BIGINT       NOT NULL DEFAULT 0 COMMENT '删除标记。0未删除；删除后写入非0唯一值',
    PRIMARY KEY (rule_id, is_deleted)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='口语到标准病名的归约规则。只有 REVIEWED 参与挂科';
```

写入校验（`LexiconWriteRules.validateSynonym`）：

- `target_term` 必须是快照里已开通二级的 DISEASE 词；
- 每组至少 1 个词，每词 ≥ 2 字；
- `pattern` 必须能编译，且只能含数字、`血压/血糖/体温/心率` 等前缀（白名单正则检查）；
- 状态只能 DRAFT → REVIEWED → RETIRED，REVIEWED 必须带 `reviewer`。

种子示例（DRAFT 入库，审核后转 REVIEWED）：

| rule_id | target | all_groups | pattern |
|---|---|---|---|
| SYN-HTN-001 | 高血压 | `[["血压高","血压偏高","血压升高","血压上去了"]]` | — |
| SYN-HTN-002 | 高血压 | `[["血压","高压"]]` | `(血压|高压)(1[4-9]\d|2\d\d)` |
| SYN-DM-001 | 糖尿病 | `[["血糖高","血糖偏高","空腹血糖"]]` | — |
| SYN-DM-002 | 糖尿病 | `[["口渴","喝水多","老想喝水"],["尿多","夜尿","老跑厕所"]]` | — |
| SYN-GOUT-001 | 痛风 | `[["尿酸高","尿酸偏高"]]` | — |

## 4. 模型网关与两个模型调用方

### 4.1 `infrastructure/model/ModelGateway.java`（新）

```java
public final class ModelGateway {
    public ModelGateway(ModelProperties props, StringRedisTemplate redis, MeterRegistry meters) {}

    /** 一次调用。限流、熔断、超时都在这里；不打印原文。 */
    public ModelReply chat(ModelPurpose purpose, String system, String user, String cacheKey) {}
}

public enum ModelPurpose { SAFETY, COMPLAINT }

public record ModelReply(ModelStatus status, String content, long latencyMs, String modelName, boolean cached) {}
```

行为：

1. `cacheKey != null` 且 Redis 命中 → `SUCCESS, cached=true`。Redis 异常直接跳过缓存。
2. 熔断器（每个 purpose 一个）：最近 20 次失败率 ≥ 50% → 打开 30s；打开时立即返回 `BREAKER_OPEN`；之后放 1 次探测。
3. `Semaphore.tryAcquire(acquireWaitMs)` 失败 → `BUSY`。
4. 缺 `apiKey` → `UNAVAILABLE`，启动时 WARN 一次；`prod` profile 下缺密钥直接启动失败。
5. HTTP 超时 → `TIMEOUT`；≥400 或异常 → `UNAVAILABLE`。
6. 成功且调用方校验通过后，调用方再调 `gateway.remember(cacheKey, content)` 写缓存（TTL 7 天），避免缓存不合格输出。

`ModelStatus` 增加 `BUSY(6)`、`BREAKER_OPEN(7)`；`DISABLED(0)` 保留给历史审计。

你是挂号分诊助手，只做归类，不做诊断。只输出 JSON：
{"terms":[{"term":"","evidence":""}],"specialty":"","evidence":""}
terms：患者当前主诉最可能对应的病种，只能从【病种】里选，最多2个；对应不上就 []。

## 10. 独立工作流：占坑释放（N9）

不计入准确率，单列。

```sql
CREATE TABLE IF NOT EXISTS consult_doctor_occupancy (
    order_id      VARCHAR(64)  NOT NULL COMMENT '订单号，幂等键',
    doctor_id     VARCHAR(64)  NOT NULL COMMENT '医生编号',
    schedule_id   VARCHAR(64)  NOT NULL COMMENT '排班编号',
    status        TINYINT      NOT NULL COMMENT '1占用中 2已释放-问诊结束 3已释放-取消退款 4已释放-超时',
    occupied_at   DATETIME(3)  NOT NULL COMMENT '占用时间',
    released_at   DATETIME(3)  NULL     COMMENT '释放时间',
    remark        VARCHAR(400) NULL     COMMENT '备注',
    created_by    VARCHAR(100) NULL     COMMENT '创建人',
    updated_by    VARCHAR(100) NULL     COMMENT '修改人',
    created_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
    updated_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '更新时间',
    is_deleted    BIGINT       NOT NULL DEFAULT 0 COMMENT '删除标记。0未删除；删除后写入非0唯一值',
    PRIMARY KEY (order_id, is_deleted),
    KEY idx_occupancy_doctor (doctor_id, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='医生占坑记录，释放幂等';
```

- `DoctorAssignService.assign`：同一 `orderId` 已有记录 → 直接返回原医生（重试幂等）；否则 occupy 成功后插一行。
- `POST /internal/doctors/release {orderId, reason}`：`UPDATE ... SET status=? WHERE order_id=? AND status=1`，影响 1 行才 `in_flight-1`；`reason=取消退款` 时再 `remain_num+1`。
- 触发点：管理端/医生端「结束问诊」；`OccupancyReaper` 每 5 分钟把 `occupied_at` 超过 `consult.identity.occupancy-ttl-minutes`（默认 30）的记录按超时释放。
- 测试：重复释放只减一次；超时释放后可再派；取消退款恢复号源。
