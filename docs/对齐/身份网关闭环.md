# 身份、就诊人与网关闭环

进咨询前必须登录。与互联网医院同一条产品线：账号 ≠ 就诊人，一个账号多名就诊人，本轮咨询只绑一位。运行时不依赖 cloudHosServer，逻辑重写。旧库只做迁入。

必要的 HIS 管理后台在本仓库：工作人员登录后可看账号、就诊人、咨询会话、科室目录。不是旧 HIS 工程的拷贝。

## 进程

| 进程 | 端口 | 职责 |
|---|---|---|
| consult-gateway | 8080 | 鉴权、路由、跨域。唯一对外入口 |
| consult-identity | 18082 | 短信登录、账号、就诊人、工作人员 |
| consult-registration-agent | 18081 | 挂号咨询。只认网关传入的账号 |
| consult-registration-web | 5173 | 患者登录页 → 咨询页 |
| consult-admin-web | 5175 | HIS 管理后台 |

开发时 Vite 把 `/api` 转到网关 `8080`。

## 表

- `consult_account`：登录账号（手机号）。对应旧 `dic_patient_user`
- `consult_person`：自然人档案。对应旧 `pro_patient`
- `consult_account_patient`：账号↔档案绑定。对应旧 `pro_of_patient`
- `consult_staff`：管理端工作人员

`legacy_user_id` / `legacy_patient_id` 只给迁移对账，接口不暴露。

## 鉴权

1. `POST /api/auth/sms`、`POST /api/auth/login`、`POST /api/admin/login` 匿名
2. 其它 `/api/**` 必须 `Authorization: Bearer`
3. 网关校验 JWT，写入 `X-Account-Id`，去掉客户端自带的该头
4. 患者令牌 `role=patient`，工作人员 `role=staff`。管理接口只接受 staff
5. 咨询、就诊人接口没有账号则业务码 1201，不再落到 `demo`

演示环境短信验证码默认 `000000`。管理端演示账号 `admin` / `admin1234`。密钥和密码只从本机 yml 或环境变量读。

## 咨询衔接

未登录不能进咨询页。登录后发主诉 → 选/新建就诊人 → 绑到本轮 → 出卡。

## 管理端

- 身份服务：`/api/admin/login`、`/api/admin/me`、`/api/admin/accounts`、`/api/admin/patients`、`/api/admin/doctors`、`/api/admin/schedules`
- 咨询服务：`/api/admin/consultations`、`/api/admin/departments`

医生档案对应旧 `dic_doctor` 精简；出诊排班对应旧 `pro_visit_real` 精简（日期+上下午+限号）。不落模板表、不接旧 Feign。

医生档案一级科室（`department_code`）、二级科室（`specialty`）、擅长（`skills`）分列，简介不参与匹配。支付后内部 `POST /internal/doctors/assign`：先卡二级科，再按擅长最长命中；挂上占号源和并发（图文默认 3 单）。高血压+普内科优先赵衡。
