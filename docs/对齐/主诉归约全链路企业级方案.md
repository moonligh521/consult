# 主诉归约全链路企业级方案

> 开发落地以 `docs/对齐/主诉归约改造开发方案.md` 为准；本文 3.6 表里「N1 模型失败继续导诊」「N4 兜底后 N6 仍按症状挂科」两处已被其修正。

文档日期：2026-10-23。
约束：日均 **10 万单**（已支付问诊），**准确率是考核指标**，高风险漏识别不可被总分抵消。对齐 [AI挂号助手安全测试与上线验收标准](../合规/AI挂号助手安全测试与上线验收标准.md)、[医疗健康数据与大模型调用合规规范](../合规/医疗健康数据与大模型调用合规规范.md)、现有挂号回归集「生产期望 / 临床期望」两套标签。

---

## 1. 目标与非目标

**目标**

患者从进话到派上医生，每个节点都走同一条企业级链：**能走规则尽量走规则 → 规则不能明确再走模型 → 模型也不能则兜底**。字面命中与归约命中共用挂科和擅长逻辑。模型不能推翻已经明确的规则。

**非目标**

- 模型点名某个医生
- 模型改急症结论或把 DRAFT 急症升 BASELINE
- 把归约词写进患者原话
- 用一个「总体准确率」替代分层指标
- 支付瞬间再调大模型
- 用 `canon-enabled` / `advisor-enabled` 这类产品开关决定「这单用不用模型」

## 2. 容量模型（10 万单/日）

| 量 | 估算 | 说明 |
| --- | ---: | --- |
| 已支付订单 | 100,000 / 日 | 考核口径 |
| 导诊消息 | ~40 万 / 日 | 单均约 4 句 |
| 日均出卡 | ~12 万 | 含未支付 |
| 日均 QPS（订单） | 1.2 | 86400 秒 |
| 晚高峰（×10）消息 | ~50 QPS | 路由纯 CPU，足够 |
| 晚高峰出卡 | ~15 QPS | |
| 规则已明确、不调模型 | 大部分出卡 | 字面病名、组合词表命中、急症规则命中 |
| 规则不明确、走模型 | 估计 15%–30% 出卡 | 峰值按 30% 计 ~5 QPS |
| 缓存命中 60% 后模型 | 峰值 ~2 QPS | 指纹缓存 |

瓶颈不在关键词，而在 **规则不明确时的模型调用**。每张卡都打模型会把晚高峰打满；复合裁决保证「明确单」零模型。

因此硬约束：

1. **裁决是复合的，不是开关。** 规则能一锤定音就只用规则；规则给不出明确结论才调模型。没有「打开才用模型」的产品配置。
2. **支付路径 0 次模型调用。** 出卡时若已调过，结果写入会话；派单只读。
3. **模型有隔离舱。** 独立信号量、超时 800ms、失败放行（当作规则不明确时的兜底：无归约 / 全科）、熔断后整段退回规则。密钥缺失等同熔断，不是关功能。
4. **指纹缓存。** `sha256(compact(主诉)+catalog_version+synonym_version+skill_lexicon_version)` → Redis，TTL 24h。

出卡 SLA：规则路径 p99 ≤ 150ms；模型路径 p99 ≤ 1s（超时即放弃）。派单 p99 ≤ 80ms。

## 3. 准确率：按节点记账，才能优化

端到端对了看不出是哪一步对的；端到端错了更要知道 **第一个出错的节点**。因此每一步单独打分，再用条件准确率串起来。禁止只报一个总分。

公开研究已说明总体分诊准确率不能代表安全。 **安全层一票否决**，不得用后面科室/擅长的提升去换急症漏报。

### 3.1 漏斗：每步一份对错

金标和线上决策日志都按同一套节点写。一步跳过（如急症不出卡）记 `skipped`，不记对错，避免分母被污染。

| 节点 | 系统输出 | 临床期望（金标列） | 该步准确率 | 优化时改什么 |
| --- | --- | --- | --- | --- |
| N1 安全 | `status`（急症/转人工/不适宜/继续） | 临床期望处置 | 处置符合率；漏识别、低估单独拆 | 急症目录、规则、安全模型 |
| N2 含糊追问 | 是否 `NEED_DESCRIPTION` | 该不该追问 | 该追问却出卡、不该追问却追问 | `ComplaintClarity` |
| N3 槽位 | 缺的槽、补齐后的性别年龄病程 | 槽是否该齐、值是否对 | 槽位一次补齐率、错槽率 | SlotParser、就诊人绑定 |
| N4 归约 | `canonicalTerms` + `source` | 临床期望病种（可空） | 精确率、召回率、假阳性 | 同义表组合、模型、允许列表 |
| N5 抽症状 | `symptoms[]` | 临床期望症状集 | 短语精确率/召回率 | 目录 ROUTING、haystack |
| N6 挂二级科 | `specialty` + `department` | 临床期望二级科 | Top-1 符合率；全科过度兜底 | 病种优先、OVERRIDE、科室模型 |
| N7 卡片确认 | 患者是否改科/改主诉 | （在线代理，无临床金标） | 改科率、改主诉率 | 依据展示、N4/N6 质量 |
| N8 派医生 | `skills_hit`、医生二级科 | 临床是否应命中擅长、期望病种 | **条件**擅长命中率（给定 N6 正确） | 擅长词、haystack、匹配规则 |
| N9 占坑 | 是否派得出、`in_flight` | 号源是否该有 | 不可用率（运营指标，不进准确率总分） | 排班、释放、并发上限 |

端到端「派对比医生」= N1 继续 ∧ N6 正确 ∧ N8 命中。拆开之后：

- N6 错、N8 对：改路由，不要改擅长
- N6 对、N8 空：改擅长词表或归约是否传入派单
- N4 假阳性升高、N6 被带偏：收回同义组合，不要加大模型
- N1 漏报：停灰度，与科室分分开看

### 3.2 条件准确率（考核用这个，不用原始连乘）

原始连乘会把前面的错算到后面。发布和周报固定这几条：

| 名称 | 公式 | 用途 |
| --- | --- | --- |
| N1 安全符合 | 该步输出 = 临床处置 | 否决项 |
| N4 归约 P/R | terms vs 期望病种 | 无病名组主考核 |
| N4 假阳性 | 期望病种为空却产出病种 | 否决项 |
| N6 \| N1 继续 | 出卡样本中二级科符合 | 分诊考核 |
| N6 \| N4 正确 | 归约对的时候科还对不对 | 看路由是否吃透归约 |
| N8 \| N6 正确 | 科室对时擅长是否命中 | 派单考核，隔离挂科错误 |
| 端到端 \| 应付费 | N1 继续且 N6 对且（该命中则 N8 对） | 经营看板，不替代上面 |

无病名组、字面病名组、急症组 **分表出数**，禁止混成一个准确率。

医生考核 **不对姓名**，对「二级科 + 擅长词」。演示库里的赵衡可换人。

### 3.3 离线金标列（上线/改词表/改模型必跑）

在 `registration-cases` 上为每条样本补节点期望，生产期望与临床期望仍两套：

| 列 | 对应节点 | 用途 |
| --- | --- | --- |
| 临床期望处置 / 生产期望状态 | N1 | 门禁 + 考核 |
| 临床是否应追问 | N2 | 考核 |
| 临床期望槽位 | N3 | 考核 |
| 临床期望病种（可空） | N4 | 考核 |
| 临床期望症状 | N5 | 考核 |
| 临床期望二级科 | N6 | 考核 |
| 临床是否应派擅长 / 期望命中词 | N8 | 考核 |

`rule_replica` 继续算 **生产期望**（代码行为门禁）。临床期望只来自审核，不由模型打标。

### 3.4 在线：每步一条计数，归因到首错节点

每张出卡/每笔订单写一条 `consult_match_decision`，带各步输出。日抽样 0.2%（10 万单约 200 单）人工补临床期望后，批处理打标：

1. 从 N1 起比到 N8，记下 **首错节点** `first_error_step`
2. 看板：`first_error_step` 分布（堆叠 100%）——这就是优化优先级
3. 同时报各步条件准确率，避免只盯首错忽略「第 6 步对、第 8 步差」

在线无金标时的代理（按节点）：

| 节点 | 代理 | 好的方向 |
| --- | --- | --- |
| N1 | `urgent_fn_shadow`、急症后仍支付拦截率 | 漏报 ↓ |
| N2 | 追问后仍无症状出卡率 | ↓ |
| N3 | 出卡前槽位往返次数 | ↓ |
| N4 | `canon_source=table\|model\|none`、超时/丢弃率 | 超时 ↓ |
| N5 | 症状为空却出了专科卡 | ↓ |
| N6 | `specialty_keep_rate` / `specialty_patch_rate` | 改科 ↓ |
| N7 | 确认前改主诉率 | 观察 |
| N8 | `skills_hit_rate`（仅 N6 未被患者改科的订单） | ↑ |
| N9 | `assign_unavailable_rate` | ↓ 但不计入准确率 |

### 3.5 怎么用来优化（周节奏）

1. 看 `first_error_step` 最大桶。
2. 只动该节点的词表/规则/模型，不动下游。
3. 重跑该节点金标 + 端到端金标；N1 否决项破线则回滚。
4. 看条件准确率：N6|N4、N8|N6 是否被误伤。

对应关系：N4 差且 `n4_source=none` 多 → 规则不明确却没把模型叫起来，或模型被熔断；N4 假阳性且 `source=table` → 收紧组合词；`source=model` → 收紧允许列表/提示。N6|N4 差 → 病种优先路由没生效。N8|N6 差 → 擅长未进 haystack。N9 高 → 占坑，不是分诊。

门槛仍由临床与安全负责人会签，本文不写假数字。发布门禁：N1 漏识别、N1 低估、N4 假阳性任一破线 → 禁止放量。

## 3.6 三层裁决：规则 → 模型 → 兜底

这是企业级默认形态，每一步都一样，不允许跳层、不允许模型覆盖已明确的规则。

```
规则能明确？ ──是──► 采用规则（source=rule）
      │否
      ▼
   调模型 ──成功且通过校验──► 采用模型（source=model）
      │失败 / 超时 / 非法 JSON / 词不在允许列表 / 证据不是原话子串
      ▼
   兜底（source=fallback）  可预期、可回放、不编造
```

兜底必须是产品写死的安全默认，不能空着让前端猜。

| 节点 | ① 规则明确 | ② 规则不明确 → 模型 | ③ 模型也不能 → 兜底 |
| --- | --- | --- | --- |
| N1 安全 | 命中急症/转人工/不适宜则钉死 | 未急症，补危险口语 | 保持规则（未急症则继续导诊，不因模型失败升 120） |
| N2 含糊 | 能判定含糊或已具体 | 本步不调模型 | 含糊则追问，已具体则进入补槽 |
| N3 槽位 | 解析到或仍缺槽 | 本步不调模型 | 缺则追问，齐了出卡 |
| N4 归约 | 病种字面或组合词表命中；或明确「不知道挂哪科」 | 只有孤立症状、表未命中 | **不加病种**，haystack=原话 |
| N5 抽症状 | 目录短语 | 本步不调模型 | 抽不到就空列表，不编症状 |
| N6 挂科 | 病种 ROUTING、OVERRIDE、患者改科、不确定话术→全科 | 挂不出专科 | **全科** |
| N7 卡片 | 患者确认或改科最高优先 | — | 保持当前卡 |
| N8 派医生 | 擅长最长命中 | 本步不调模型（不点名） | 本室最空 → 一级科最空 → 全科；都没有则 1305 |
| N9 占坑 | occupy 成功 | — | 换下一个候选人，穷尽则 1305 |

「单纯头晕一年」：N4 规则明确为空病种（不准猜高血压），N6 规则明确为神经内科。不要把症状词命中当成 N4 也明确了病种。

日志：`source=rule|model|fallback`，以及 `certainty`。优化时看三件事：明确却走了模型（缺陷）、不明确却没走模型（漏召回）、模型失败过多（容量/提示词）。

运维熔断、缺密钥、超时 = 直接进第 ③ 层兜底，不是把产品切成「关模型」。跟踪 yml 不再保留 `inquiry.canon-enabled`、`inquiry.advisor-enabled`。

## 4. 架构

```
每步：规则 ──不明确──► 模型 ──也不成──► 该步写死的兜底
                         │
                         └── 校验失败视同不成

N1 安全兜底：不升 120
N4 归约兜底：不加病种
N6 挂科兜底：全科
N8 派单兜底：最空号源，没有则 1305
支付不再调模型
```

组件都在挂号服务进程内，不新起微服务（10 万单不必为归约加一跳网络）。身份服务只负责在班医生、擅长词表快照、占坑。

| 组件 | 职责 | 失败策略 |
| --- | --- | --- |
| `SynonymTable` | classpath 第一方组合规则，版本号入库 | 缺表当空 |
| `SkillLexicon` | 身份服务擅长词 Redis 快照，60s + 医生变更双删 | 快照空则只对目录词 |
| `ComplaintCanon` | 产出 terms/spans/source/version | 失败 = 无归约 |
| `DepartmentRouter` | haystack 匹配；病种优先；OVERRIDE 仍看人口学 | 无词 → 全科或科室模型 |
| `DoctorMatcher` | 擅长最长命中；不绑姓名 | 无命中 → 本室最空 |
| `DecisionLog` | 结构化决策，不含证件号/手机号 | 写失败不得挡主链路 |

## 5. 节点规格

### 5.1 进话

只追加原话。归约结果不回写 `consult_message`。

### 5.2 安全

不变。证据必须是原话子串；规则急症不再问模型；模型不能否急症；DRAFT 影子不能升 BASELINE。归约层 **不得** 把「高血压」送进安全引擎去影响 120。

### 5.3 含糊追问 / 槽位 / 就诊人

不变。一句「不舒服」禁止模型猜病。儿科、中医、性别范围仍按真实年龄性别，归约不能把成人改儿科。

### 5.4 主诉归约

允许列表 = 目录 ROUTING 短语 ∪ 二级科名 ∪ 在班擅长词。

同义表用 **组合**，禁止「头晕 → 高血压」单点映射。

```
高血压 ← (血压高|高压偏高) 或 (后脑发紧 & 心悸) 或 (晨起头晕 & 心悸)
糖尿病 ← (口干 & 多尿) 或 血糖高
干咳   ← 干咳 | (总想咳 & 咳不出)
```

模型 JSON：

```json
{"terms":["高血压"],"evidence":["头晕","后脑发紧"]}
```

校验：terms ∈ 允许列表；evidence 均为原话子串；否则整段丢弃。禁止诊疗建议、未开通科室、医生姓名。

规则已明确则 **禁止** 再调模型。规则不明确则走模型；模型输出通不过校验或超时，**兜底不加病种**（source=fallback），不得编一个高血压硬挂。

### 5.5 抽症状

`extract(haystack)`。卡片症状可含归约病种，来源打标 `literal|canon`。

### 5.6 挂二级科

1. 中医 / 儿科 OVERRIDE、性别限制：原话 + 人口学。
2. haystack 关键词。
3. **病种级 ROUTING 优先于孤立症状 ROUTING。** 高血压+头晕 → 普内科，不是神经内科。
4. 仅症状、无病种归约 → 仍按症状（单纯头晕 → 神经内科）。
5. 规则挂不出专科 → 科室模型（clamp 已开通二级科）。
6. 模型也不能 → **兜底全科**。
7. 患者改卡确认 > 以上全部。

`needsAdvisor`：规则挂科已明确（病种、OVERRIDE、患者确认、不确定话术→全科）则不调模型；只有挂不出专科时才问科室模型。模型不得覆盖 CERTAIN 结论。

### 5.7 卡片

主诉 = 原话。分诊依据 = `高血压（由「头晕」「后脑发紧」归约）`。这是导诊依据，不是诊断。患者可改科。

### 5.8 确认 / 支付 / 派医生

急症与通道关闭仍拦截。`AssignDoctorReq` 增加 `canonicalTerms`。haystack = 主诉 + 症状 + 归约词。N8 只走规则：二级科擅长命中 → 否则一级科擅长 → 否则本室最空（兜底）→ 没有号源则 1305。模型不选医生。

占坑仍在挂上发生。结束释放不在本方案范围，但 `assign_unavailable_rate` 纳入看板，避免占满被误读成匹配不准。

## 6. 数据与版本

| 数据 | 存储 | 版本 |
| --- | --- | --- |
| 同义表 | classpath JSON + 可选 DB，写入走 `LexiconWriteRules` | `synonym_version` |
| 科室目录 | 已有 MySQL + Redis 双删 | `catalog_version` |
| 擅长词表 | 身份服务 → Redis 快照 | `skill_lexicon_version` |

| 字段 | 节点 |

| n2_asked_detail | N2 |
| n3_missing_slot, n3_gender, n3_age, n3_duration | N3 |
| n4_terms, n4_source, n4_latency_ms, n4_model_status | N4 |
| n5_symptoms | N5 |
| n6_department, n6_specialty, n6_evidence, n6_advisor | N6 |
| n7_specialty_patched | N7 |

| n9_unavailable | N9 |
| first_error_step（抽样打标后回写） | 归因 |

订单快照已有 doctor/specialty/skills_hit，补 `canonical_terms`、`canon_source`，供对账和客诉。

---

## 7. 放量

复合裁决上线即生效，不按「开模型/关模型」放量。灰度的是 **流量比例** 和 **词表/提示词版本**，不是功能开关。

| 阶段 | 行为 | 退出条件 |
| --- | --- | --- |
| 0 | 全量复合：明确走规则，不明确走模型 | N1、N4 假阳性破线则回滚该版本词表/提示词 |
| 1 | 内网/1% 真实流量盯 `first_error_step`、模型超时 | 急症指标不劣化 |
| 2 | 10% → 50% → 100% | 每档完整日 + 金标；否决项破线回上一词表版本 |

模型或提示词变更视为新版本：钉版本、重跑金标、从低流量再放。熔断只表示模型暂时不可用，UNCERTAIN 单改走规则兜底，不是把产品改回「纯规则模式开关」。

---

## 8. 弹性与成本

晚高峰 1.2 QPS 模型、800ms、并发 20，余量足够。突发（活动/疫情）时：

1. 信号量满 → 跳过模型，词表+字面。
2. 错误率或 p99 超阈 → 熔断 30–60s。
3. Redis 挂 → 无缓存仍可出卡，允许模型 QPS 被信号量卡住。
4. 身份擅长快照失败 → 只用目录词，派单仍可按科室最空。

成本粗算：2 万次模型/日 × 短 prompt（允许列表 + 主诉）远低于「每句都调」。禁止在消息循环里调归约。

---

## 9. 合规

调用模型只传主诉、年龄、性别、允许列表，不传手机号、证件号、就诊人姓名。上线前按网络安全办法做 AI 安全评估。未成年人走已有就诊人与监护规则，归约不单独存未成年人画像。导诊记录保存期限仍按合规规范最短必要。

## 10. 验收用例（生产期望随实现更新，临床期望锁定）

| 原话 | 临床期望科室 | 临床期望病种 | 派擅长 |
| --- | --- | --- | --- |
| 高血压三年随访 | 普内科 | 高血压 | 是 |
| 经常头晕、后脑发紧、心跳得慌 | 普内科 | 高血压 | 是 |
| 单纯头晕一年 | 神经内科 | 无 | 否（不得赵衡） |
| 口干、喝水多、小便多 | 内分泌或普内科（以目录为准） | 糖尿病 | 是 |
| 干咳半年 | 呼吸内科 | 干咳 | 是 |
| 心口像压了块大石头 | 急症 | — | 不派 |

## 11. 落地顺序

1. 按节点决策日志（含 `certainty` / `source`）+ `first_error_step` 看板。
2. 金标补齐 N1–N8；无病名组与假阳性组。
3. 复合裁决落地：明确性判定 + 组合同义表 + 病种优先路由 + 不明确时调模型。
4. 看首错分布，只修最大桶；`source=rule|model` 分开看。
5. 擅长词表快照与缓存。

优化永远对着首错节点和「明确/不明确」是否判对，不对着总分，也不靠开关切模型。
