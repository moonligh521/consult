# 观测栈部署

现网：Langfuse 和 OTLP Collector 在 `117.72.43.169`。对象存储用已有 MinIO `154.8.236.238:9000`，桶名 `langfuse`。不要和业务 MySQL / Redis 共用，也不要把服务写进业务 compose。

本机 Java → `http://117.72.43.169:4318/v1/traces` → otel-collector → Langfuse。

## 拷到服务器的文件

放到同一目录（现网是 compose 所在目录，不是 `/root/local` 也没关系）：

- `deploy/compose/observability-compose.yml`
- `deploy/compose/otel-collector.yml`

`otel-collector.yml` 必须是普通文件。`ls -l otel-collector.yml` 要能看到字节数。若输出是「总用量 0」，说明被 Docker 建成了空目录，Collector 会 Restarting。处理：

```bash
docker-compose -f observability-compose.yml stop otel-collector
rm -rf otel-collector.yml
```

再把仓库里的 `otel-collector.yml` 拷回去。重新 `docker load` 镜像 tar **不会**再把它变成空目录。

防火墙开 `3000`（页面）和 `4318`（本机送 trace）。`154.8.236.238` 要放行 `117.72.43.169` 访问 `9000`。MinIO 控制台先建好桶 `langfuse`，不要用 `milvus-bucket`。

## 1. 本机拉取镜像

服务器访问不了 Docker Hub，在能联网的 Windows 上逐条 pull。不含 MinIO。

```bat
docker pull otel/opentelemetry-collector-contrib:0.136.0
docker pull docker.langfuse.com/langfuse/langfuse-worker:3.117.0
docker pull docker.langfuse.com/langfuse/langfuse:3.117.0
docker pull docker.io/clickhouse/clickhouse-server:26.3.62.3
docker pull docker.io/redis:7.4.2
docker pull docker.io/postgres:17.5
```

## 2. 本机打包

在 **cmd** 里一行执行。不要用 PowerShell 的反引号续行，cmd 会把每一行当成新命令。

```bat
docker save -o observability-images.tar otel/opentelemetry-collector-contrib:0.136.0 docker.langfuse.com/langfuse/langfuse-worker:3.117.0 docker.langfuse.com/langfuse/langfuse:3.117.0 docker.io/clickhouse/clickhouse-server:26.3.62.3 docker.io/redis:7.4.2 docker.io/postgres:17.5
```

完整包约 `4009557504` 字节（3.73GB）。不要把 tar 提交进 git。

```bat
dir observability-images.tar
scp observability-images.tar root@117.72.43.169:/root/local/observability-images.tar
```

## 3. 服务器加载

两边文件大小必须一致。用 `-i`，不要用 `<`（传不完整时会 `unexpected EOF`）。

```bash
ls -l observability-images.tar
docker load -i observability-images.tar
docker images
```

这六个都在即可：

- `otel/opentelemetry-collector-contrib:0.136.0`
- `docker.langfuse.com/langfuse/langfuse:3.117.0`
- `docker.langfuse.com/langfuse/langfuse-worker:3.117.0`
- `clickhouse/clickhouse-server:26.3.62.3`
- `redis:7.4.2`
- `postgres:17.5`

`docker.io/` 前缀和短名是同一个镜像，不会因为名字去重新拉。

## 4. 启动

```bash
docker-compose -f observability-compose.yml up -d
docker-compose -f observability-compose.yml ps
```

第一次 ClickHouse 迁移可能超过两分钟。若 web 仍 unhealthy 但页面已通，只补 Collector：

```bash
docker-compose -f observability-compose.yml up -d --no-deps --force-recreate otel-collector
```

`ENCRYPTION_KEY` 必须带引号，否则 YAML 把 64 个 0 解析成数字 `0`，Langfuse 起不来。

## 6. 踩坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `registry-1.docker.io` 超时 | 服务器访问不了 Docker Hub | 本机 pull 打 tar 再 load |
| `docker save` 报「不是内部命令」 | cmd 里用了 PowerShell 续行 | 一行打完 |
| `docker load` unexpected EOF | 没传完整 | 两边文件大小必须一致 |
| `ai-net declared as external` | 这台机器原先没有这个网 | compose 自己创建 `ai-net` |
| Langfuse `ENCRYPTION_KEY too_small` | YAML 把一串 0 解析成数字 | 加引号 |
| web 显示 unhealthy，页面其实能开 | 镜像里没有 `wget` | 健康检查用 node fetch |
| collector `Up (unhealthy)` 但 trace 能进 | 0.136 镜像没有 wget，compose 探活失败 | `healthcheck.disable: true`，以 4318 为准 |
| collector：`config.yaml: is a directory` | 同目录没有 yml 文件 | 删空目录，放入真正的文件 |
| tar 包有没有问题 | 完整包没问题 | 第一次 load 失败是传输截断 |
