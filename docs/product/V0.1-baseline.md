## 本版交付

患者用一句话描述病情。系统一次只补一个缺失槽位，直到性别、年龄、病程都齐。然后抽出症状标签，按下面的关键词规则推荐一个科室，并生成咨询卡片。确认前可以修改。确认后给出结果，不连接号源，不创建订单。

病情、科室和对话都使用合成数据。

### 槽位

一次只追问一个缺失项，顺序固定为：性别、年龄、病程。

| 槽位 | 合格值 | 不合格时 |
| --- | --- | --- |
| 性别 | 男、女 | 继续追问性别 |
| 年龄 | 1 到 120 的整数岁 | 继续追问年龄 |
| 病程 | 能读出时长，例如「两小时」「三天」「半年」 | 继续追问病程 |

空白输入不进入抽槽，提示重新描述病情。

### 症状与科室

从用户描述中抽出症状短语，不使用疾病编码。科室只由下表决定。一句话里有多个关键词时，采用文中先出现的那个关键词。

| 先出现的关键词 | 推荐科室 |
| --- | --- |
| 咳、气促、呼吸 | 呼吸内科 |
| 胸痛 | 心血管内科 |
| 头痛、头晕 | 神经内科 |
| 腹痛、腹泻、恶心 | 消化内科 |
| 以上都没有 | 全科医学科 |

### 咨询卡片

三个槽位齐全后才生成卡片。字段为：

- 性别
- 年龄
- 病程
- 病情描述：用户原话；多轮补充按时间顺序拼接
- 症状标签
- 推荐科室

确认前允许修改这些字段。只改性别、年龄或病程时，症状标签和推荐科室保持不变。改了病情描述时，按新描述重算症状标签和推荐科室。用户直接改了推荐科室时，保留用户选择的科室，规则不再覆盖。

确认结果保存用户最终确认的卡片。本版不扣减号源。

模型可以协助组织追问语句。槽位是否齐全、症状标签和推荐科室以本节规则为准。

## 验收用例

| 编号 | 输入 | 通过标准 |
| --- | --- | --- |
| AC-1 | 女，32岁，干咳半年，运动后加重 | 不再追问。卡片为女、32 岁、半年；症状含干咳；科室为呼吸内科 |
| AC-2 | 男，干咳三天 | 只追问年龄。不生成卡片 |
| AC-3 | 女，28岁，头痛 | 只追问病程。不生成卡片 |
| AC-4 | 45岁，胸痛两小时 | 只追问性别。不生成卡片 |
| AC-5 | 在 AC-1 的卡片上把科室改为全科医学科后确认 | 确认结果的科室是全科医学科 |
| AC-6 | 在 AC-1 的卡片上把病情改为「腹痛两天」 | 症状改为腹痛，科室改为消化内科 |
| AC-7 | 空白 | 提示重新描述病情。不生成卡片 |

AC-2、AC-3、AC-4 在补齐缺失槽位后，按同一规则生成卡片。

## 完成定义

V0.1 同时满足下面各项，才可以合入 `main` 并打 `V0.1.0`：

- 构建使用 JDK 21、Spring Boot 4.1.1、Spring AI 2.0.1，包名位于 `com.moonligh.registration`
- 仓库包含可启动入口、示例配置，且示例配置不含密钥和真实病历
- AC-1 到 AC-7 都有自动化测试，并且通过
- 合并请求的检查至少包含编译和测试
- `CHANGELOG.md` 的 `Unreleased` 已归入 `V0.1.0`
