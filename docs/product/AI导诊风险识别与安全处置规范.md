# AI 导诊风险识别与安全处置规范

规范日期：2026-10-21。

本文把 [AI 挂号助手合规边界与适用场景评估](AI挂号助手合规边界与适用场景评估.md) 里的安全分流写成可执行规则。触发条件的临床清单由医疗专业人员审核后才能用于真实患者。本文列出的表现是规则应覆盖的类型，不是完整临床标准。

## 结论

高风险识别独立于大模型。模型可以提取症状和缺失信息，不能决定忽略已经触发的高风险信号。

安全引擎不可用时，不得把本次请求默认成低风险，不得继续普通预约。

## 三种处置

这三种处置是产品安全设计，不是对所有症状的法定分级。

| 处置 | 系统行为 |
| --- | --- |
| 普通导诊 | 继续收集完成本次预约所必需的信息，给出科室候选和就诊方式 |
| 需要线下评估 | 停止诊断性判断。按已审核规则提示实体医疗机构或相应就诊方式。是否继续普通预约，由该规则决定，不得为了完成预约减弱风险提示 |
| 疑似急危重症 | 立即给出紧急求助。在中国大陆提示拨打 120，并说明前往最近实体医院急诊。不得先收集完长表单、选择医生或确认支付，再显示该提示 |

「终止互联网诊疗」只停止诊疗问答和诊疗结论。紧急求助、急诊入口和实体医院信息仍然提供。互联网诊疗的首诊限制不禁止首次症状患者预约线下门诊；是否走急诊，单独判断。

## 不能只做关键词黑名单

同一风险要覆盖同义、否定、时间变化、代述和不确定表达。至少包括这类说法：

- 「胸口有点闷，但不严重。」
- 「昨天喘不过气，今天好一点了。」
- 「老人突然说话不清楚，过了一会儿又正常了。」
- 「孩子嘴唇发紫，但我想先约明天的号。」
- 「肚子特别痛，越来越疼。」
- 「我不确定是胸痛，还是胃不舒服。」

模型负责把这些说法整理成结构化信号。安全引擎根据审核后的规则决定处置。模型不得把「但不严重」「今天好一点了」解释成可以继续普通预约。

急性胸痛、呼吸困难、意识或言语突然异常、进行性加重的剧烈疼痛、口唇发紫，进入疑似急危重症的候选。最终触发条目以医疗专业人员审核的版本为准。

## 优先级

1. 疑似急危重症覆盖普通导诊和已经生成的预约候选。
2. 多轮对话中新出现的危险信号覆盖此前的普通状态。
3. 信息不足时，不得给出确定的疾病判断，也不得向用户保证「不用急诊」。
4. 信息互相矛盾、儿童、孕妇、老年人、残障人士，以及用户要求人工协助时，转入经授权的人工导诊。特殊人群的额外规则由医疗专业人员审核。

## 状态

用状态机执行，不依赖一段提示词。

| 状态 | 进入条件 | 允许的下一步 |
| --- | --- | --- |
| 普通就医需求 | 查询医院信息，或症状未触发更高处置 | 整理必要信息，匹配科室 |
| 预约候选已生成 | 科室、医生、院区、时间和规则均来自号源系统 | 用户确认后才调用预约接口。只有接口返回成功，才显示预约成功 |
| 需要线下评估 | 审核后的规则要求实体机构评估 | 给出相应提示。不输出诊断 |
| 疑似紧急情况 | 安全引擎触发急危重症 | 中止普通导诊和预约推进，先给紧急求助 |
| 需要人工协助 | 信息矛盾、特殊人群、风险不明确，或用户要求人工 | 转入医院导诊台或其他经授权渠道 |

号源接口超时或失败时，不得显示预约成功。模型没有把握时，不得编造医院、科室、医生专长或号源。

## 责任控制

科室推荐不准确、漏掉紧急症状的控制方式：

- 高风险由独立规则拦截，不由模型单独放行。
- 推荐科室时同时展示依据来自用户描述的哪些信息，并说明这不是诊断。
- 漏识别率、危险性低估率按 [安全测试与上线验收标准](AI挂号助手安全测试与上线验收标准.md) 单独统计，不用总体准确率代替。
- 规则版本、模型版本、人工干预和状态切换写入审计记录。

医疗机构依法承担其自身医疗服务和质量安全职责。挂号助手运营方承担导诊输出、预约执行和数据处理范围内的产品责任。两边的职责在合作协议里分开写明。
