# V0.1 一轮咨询

本文件规定 V0.1 的调用契约。验收标准仍以 [V0.1 交付基线](V0.1-baseline.md) 为准。这里把每一轮的输入、输出和错误定成实现时必须遵守的字段。

咨询过程保存在当前进程里。服务重启后，已有咨询编号失效。本版不做登录，也不在多实例之间共享会话。

## 咨询编号

第一轮文本没有 `consultationId` 时，服务生成编号并在响应里返回。编号是小写 UUID，形如 `6f1c3a2e-4b7d-4e1a-9c2f-0a1b2c3d4e5f`。

之后的文本、修改卡片和确认都带上这个编号，表示同一轮咨询。编号未知时返回 `CONSULTATION_NOT_FOUND`。调用方不能自己指定新编号。

## 状态

| status | 含义 | 接下来可以做什么 |
| --- | --- | --- |
| `NEED_DESCRIPTION` | 还没有可解析的病情描述 | 继续提交文本 |
| `NEED_SLOT` | 性别、年龄、病程仍有缺失 | 继续提交文本 |
| `CARD_READY` | 卡片已生成，等待修改或确认 | 修改卡片，或确认 |
| `CONFIRMED` | 已确认 | 只读。本版到此结束 |

## 提交文本

`POST /api/consultations/messages`

```json
{
  "consultationId": null,
  "text": "女，32岁，干咳半年，运动后加重"
}
```

`consultationId` 可省略。`text` 必填，允许只有空白。

响应使用同一结构：

```json
{
  "consultationId": "6f1c3a2e-4b7d-4e1a-9c2f-0a1b2c3d4e5f",
  "status": "CARD_READY",
  "prompt": null,
  "missingSlot": null,
  "card": {
    "gender": "女",
    "age": 32,
    "duration": "半年",
    "description": "女，32岁，干咳半年，运动后加重",
    "symptoms": ["干咳"],
    "department": "呼吸内科"
  }
}
```

槽位未齐时 `card` 为 `null`。追问时 `prompt` 使用下表原文，`missingSlot` 取下表的值。一次只返回下一个缺失槽位，顺序是性别、年龄、病程。

| missingSlot | prompt |
| --- | --- |
| `GENDER` | 请补充性别。 |
| `AGE` | 请补充年龄。 |
| `DURATION` | 请补充病程。 |

`text` 去掉首尾空白后为空时，不解析、不覆盖已有槽位，也不把这句写入病情描述。`card` 为 `null`。若还没有任何有效描述，`status` 为 `NEED_DESCRIPTION`，`missingSlot` 为 `null`，`prompt` 为 `请重新描述病情。`。若已经缺某个槽位，`status` 保持 `NEED_SLOT`，`missingSlot` 不变，`prompt` 仍为 `请重新描述病情。`。

非空文本按时间顺序用换行拼进病情描述。已填上的槽位不被后续文本改写。修改槽位只能走修改卡片。

`CARD_READY` 之后再提交文本，返回 `CARD_PENDING_CONFIRMATION`。`CONFIRMED` 之后再提交文本，返回 `ALREADY_CONFIRMED`。

## 从文本识别槽位

只从当前这句非空文本里补仍为空的槽位。

性别取句中先出现的「男」或「女」。「女性」视为女，「男性」视为男。

年龄取句中先出现的阿拉伯数字加「岁」，数值要在 1 到 120。`32岁` 有效。`三十二岁`、`0岁`、`121岁` 不记入年龄。

病程取句中先出现的时长短语，原样保存。短语由数字和单位组成。数字是阿拉伯数字，或由「一、二、三、四、五、六、七、八、九、十、两、半」组成。单位是「小时、天、周、个月、月、年」。因此 `半年`、`三天`、`两小时` 都有效。没有这类短语时，病程仍为空。

三个槽位在同一轮响应里第一次齐套时生成卡片。症状和科室根据当时的完整病情描述计算。

## 症状与科室

症状按在描述中出现的先后提取，同一短语只保留一次。同一位置取更长的短语。短语表为：

干咳、咳嗽、气促、呼吸困难、呼吸、胸痛、头痛、头晕、腹痛、腹泻、恶心。

`女，32岁，干咳半年，运动后加重` 的症状是 `["干咳"]`。`腹痛两天` 的症状是 `["腹痛"]`。没有命中时症状为空数组。

科室仍按基线的关键词表，取描述中位置最靠前的关键词。`咳` 能命中「干咳」里的咳，所以上一句的科室是呼吸内科。没有任何关键词时为全科医学科。

## 修改卡片

`PATCH /api/consultations/{consultationId}/card`

只在 `CARD_READY` 时可用。请求体至少包含一项：

```json
{
  "gender": "女",
  "age": 32,
  "duration": "半年",
  "description": "腹痛两天",
  "department": "全科医学科"
}
```

未出现的字段保持原值。`description` 出现时，用新文本替换整段病情描述，并按新描述重算症状和科室。同一次请求里如果也带了 `department`，科室采用请求里的值。只改性别、年龄或病程时，不重算症状和科室。

文本字段先去掉首尾空白。性别只能是「男」或「女」。年龄只能是 1 到 120 的整数。病程必须符合上一节的时长短语。科室接受任何非空白文本，可以超出规则表。

成功时 `status` 仍为 `CARD_READY`，响应里是修改后的卡片。

`NEED_DESCRIPTION` 或 `NEED_SLOT` 时修改卡片，返回 `CARD_NOT_READY`。`CONFIRMED` 时返回 `ALREADY_CONFIRMED`。请求体没有任何字段时返回 `EMPTY_CARD_PATCH`。

## 确认

`POST /api/consultations/{consultationId}/confirmation`

只在 `CARD_READY` 时可用，没有请求体。成功后 `status` 为 `CONFIRMED`，`prompt` 和 `missingSlot` 为 `null`，`card` 是用户最终确认的卡片。

其他状态下确认，分别返回 `CARD_NOT_READY` 或 `ALREADY_CONFIRMED`。

## 错误

失败时 HTTP 状态与正文如下。`message` 使用表中的原文。

| HTTP | code | message |
| --- | --- | --- |
| 404 | `CONSULTATION_NOT_FOUND` | 找不到这轮咨询。 |
| 409 | `CARD_NOT_READY` | 咨询卡片尚未生成。 |
| 409 | `CARD_PENDING_CONFIRMATION` | 请先确认或修改咨询卡片。 |
| 409 | `ALREADY_CONFIRMED` | 这轮咨询已经确认。 |
| 400 | `INVALID_GENDER` | 性别须为男或女。 |
| 400 | `INVALID_AGE` | 年龄须为 1 到 120 的整数。 |
| 400 | `INVALID_DURATION` | 病程须包含时长。 |
| 400 | `EMPTY_CARD_PATCH` | 请至少修改一项。 |

```json
{
  "code": "CARD_NOT_READY",
  "message": "咨询卡片尚未生成。"
}
```

## 验收用例怎么走

| 编号 | 调用 | 期望 |
| --- | --- | --- |
| AC-1 | 文本 `女，32岁，干咳半年，运动后加重` | `CARD_READY`。女，32，病程半年，症状正好是 `["干咳"]`，呼吸内科 |
| AC-2 | 文本 `男，干咳三天` | `NEED_SLOT`，`AGE`，提示 `请补充年龄。`，没有卡片 |
| AC-3 | 文本 `女，28岁，头痛` | `NEED_SLOT`，`DURATION`，提示 `请补充病程。`，没有卡片 |
| AC-4 | 文本 `45岁，胸痛两小时` | `NEED_SLOT`，`GENDER`，提示 `请补充性别。`，没有卡片 |
| AC-5 | 先完成 AC-1，再把科室改为 `全科医学科`，然后确认 | `CONFIRMED`，科室是全科医学科，症状仍是 `["干咳"]` |
| AC-6 | 先完成 AC-1，再把病情描述改为 `腹痛两天` | `CARD_READY`，描述为 `腹痛两天`，症状正好是 `["腹痛"]`，消化内科；性别、年龄、病程仍是女、32、半年 |
| AC-7 | 文本为空白 | 提示 `请重新描述病情。`，没有卡片 |

AC-2 的下一句若是 `32岁`，则变为 `CARD_READY`：男，32，病程三天，症状 `["干咳"]`，呼吸内科。AC-3 补 `三天`、AC-4 补 `女` 后同样生成卡片。补齐用的是新句子，病情描述按换行保留两句原文。
