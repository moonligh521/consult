# 问诊订单与医生派单

本仓库是导诊挂号的 agent 服务。它整理症状、推荐科室、按付费档位写入派单策略，并创建问诊订单。订单成功同步到医生端之后，本服务不再跟问诊过程。接诊、超时换人、图文或视频会话、诊断和处方由医生端自己完成。

V0.1 只做到咨询卡片，不创建问诊订单，不同步医生端。本文约束后续版本。

## 系统边界

| 本 agent 做 | 本 agent 不做 |
| --- | --- |
| 急症分流、多轮补槽、科室候选、咨询卡片 | 医患问诊会话 |
| 按付费档位写入派单策略（只升不降） | 医生接诊、超时换人、书写病历、开具处方 |
| 复诊核验通过后创建问诊订单 | 同步成功后再改派、再催诊、再结束问诊 |
| 把订单与策略同步到医生端，确认对端已接收 | 托管医生端的接诊界面和在线队列 |

本 agent 把问诊订单、科室、付费档位和派单策略同步给医生端。医生端执行接诊、超时换人、升档和排队。同步成功之后，本服务不再跟问诊过程，也不再改派医生。

同步失败不得对患者显示「已交给医生」。只有医生端明确接收成功，本轮 agent 才结束。结束之后，接诊结果以医生端为准。患者取消或医生端一直未接诊需要退款时，医生端回传结果，本 agent 只做退款和对账，不重开问诊。

急症分流触发时不创建问诊订单、不同步医生端。互联网诊疗的首诊限制、病历和复诊核验见 [合规边界与适用场景评估](../合规/AI挂号助手合规边界与适用场景评估.md) 与 [互联网诊疗服务边界调研报告](../合规/互联网诊疗服务边界调研报告.md)。

## 用户路径

1. 患者描述症状。信息不够，一次追问一个缺口。
2. 确认咨询卡片中的科室。
3. 选择并支付档位：普通医生、副主任医师、专家。
4. 复诊核验通过后创建问诊订单，档位写入订单，模型不能改档。
5. 将问诊订单、付费档位和下列派单策略同步到医生端。对端接收成功后，本 agent 结束这一单。
6. 医生端按策略接诊；三档都无人时在医生端排队，直到有号。

## 三档队列

下列规则写入订单的 `dispatchPolicy`，由医生端执行。本 agent 同步成功后不再改派。

医生按科室分成三档队列：普通医生、副主任医师、专家。患者付哪一档，先从哪一档匹配。

匹配顺序：

1. 从患者付费档位、且与确认科室一致的队列里，自动匹配一名在班、执业范围相符的医生。
2. 该医生超时未接或拒绝，号源回到原档，先在同一档按进入顺序换下一名。
3. 同一档无人可派，才升到上一档：普通 → 副主任医师 → 专家。只升不降。升档不补收差价。
4. 三档当时都无人，订单进入该科室等待队列，直到有号。

有号时的分配：

- 先满足 **付了这一档的人**，按进入等待的时间先后。
- 这一档没有付费等待的人，这条更高档的号才用来升级更低档、已经在排队的人。
- 付了更高档的人，即使更低档先有号，也不派低档医生。
- 某医生拒绝或超时，这一号回到原档再派，不降级给更低档。

不得虚构医生，不得在队列为空时显示已匹配、已同步。

## 同步内容

同步给医生端的订单至少包括：咨询卡片（性别、年龄、病程、病情描述、症状标签、推荐科室）、付费档位、只升不降的派单策略。接诊医生由医生端回填。身份信息按 [数据与大模型调用合规规范](../合规/医疗健康数据与大模型调用合规规范.md) 最小化传递，默认不经过模型。

医生端接收成功后返回对端订单号。本 agent 保存该号，用于对账和幂等，不再根据它推进问诊。同一问诊订单重复同步时，医生端不得生成第二单。
