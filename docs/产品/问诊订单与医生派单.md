# 问诊订单与医生派单

本仓库是导诊挂号的 agent 服务。它整理症状、推荐科室、按付费档位写入派单策略，并创建问诊订单。订单成功同步到医生端之后，本服务不再跟问诊过程。接诊、超时换人、图文或视频会话、诊断和处方由医生端自己完成。

V0.1 只做到咨询卡片，不创建问诊订单，不同步医生端。本文约束后续版本。

## 系统边界

| 本 agent 做 | 本 agent 不做 |
| --- | --- |
| 急症分流、多轮补槽、科室候选、咨询卡片 | 医患问诊会话 |
| 展示四档咨询、收款、写入派单策略 | 医生接诊、超时换人、书写病历、开具处方 |
| 复诊核验通过后创建问诊订单 | 同步成功后再改派、再催诊、再结束问诊 |
| 把订单与策略同步到医生端，确认对端已接收 | 托管医生端的接诊界面和在线队列 |

本 agent 把问诊订单、科室、付费档位和派单策略同步给医生端。医生端执行接诊、超时换人、升档和排队。同步成功之后，本服务不再跟问诊过程，也不再改派医生。

同步失败不得对患者显示「已交给医生」。只有医生端明确接收成功，本轮 agent 才结束。结束之后，接诊结果以医生端为准。患者取消或医生端一直未接诊需要退款时，医生端回传结果，本 agent 只做退款和对账，不重开问诊。

急症分流触发时不创建问诊订单、不同步医生端。互联网诊疗的首诊限制、病历和复诊核验见 [合规边界与适用场景评估](../合规/AI挂号助手合规边界与适用场景评估.md) 与 [互联网诊疗服务边界调研报告](../合规/互联网诊疗服务边界调研报告.md)。

## 用户路径

1. 患者描述症状。信息不够，一次追问一个缺口。
2. 展示咨询卡片：咨询人、咨询科室、问题描述，确认前可修改。发起咨询以修改后的信息为准。
3. 展示告知：如非复诊，仅提供医疗咨询服务。继续下单视为已知悉。
4. 进入下单页，并列四档咨询，患者选一档并支付。支付成功后立即创建问诊订单并同步医生端。
5. 医生端按该档规则接诊。本 agent 在对端接收成功后结束这一单。

急症分流触发时不进入下单页。复诊核验未通过时，告知仅提供咨询，是否仍允许下单由合作医疗机构的规则决定；互联网诊疗复诊单仍须满足 [边界调研报告](../合规/互联网诊疗服务边界调研报告.md)。

## 下单四档

下单页形态对齐常见问医生收银台：先卡片，再档位列表，点开服务详情后支付。价格由运营配置，不把某家平台的标价写进本仓库。

| 档位 | 编码 | 供给 | 服务形态 | 接诊时限（写入订单，由医生端执行） |
| --- | --- | --- | --- | --- |
| 普通咨询 | `GENERAL` | 公立医院医生，随机指派，不指定职称 | 15 分钟不限轮次 | 接诊前可取消并退款；接诊后 15 分钟未回复则退款 |
| 极速咨询 | `RAPID` | 自营医生，秒级接诊 | 15 分钟不限轮次 | 医生首次回复前可取消并退款；接诊后 15 分钟未回复则退款 |
| 三甲医生 | `TERTIARY` | 公立三甲医院医生 | 1 小时 20 轮 | 首次回复前可取消并退款；接诊后 20 分钟未回复则退款 |
| 权威专家 | `EXPERT` | 公立三甲医院 10 年以上副主任、主任医师 | 1 小时 20 轮 | 首次回复前可取消并退款；接诊后 20 分钟未回复则退款 |

各档服务时段随供给配置，同步给医生端。模型不能改档、不能改价格、不能改时限。

## 派单策略

下列规则写入订单的 `dispatchPolicy`，由医生端执行。本 agent 同步成功后不再改派。

供给分成两个池，只在池内升档，不跨池、不降档：

- 公立池：普通咨询 → 三甲医生 → 权威专家
- 自营池：极速咨询。无人时在本池排队，不升到公立，也不把公立号降给极速单

同一池内：

1. 先从患者所付档位、且与确认科室一致的队列匹配在班医生。
2. 该医生超时未接或拒绝，号源回到原档，按进入顺序换下一名。
3. 本档无人可派，才升到池内上一档。升档不补收差价。
4. 池内各档都无人，订单在医生端排队，直到有号。

有号时：先满足付了这一档的人（先到先得）；本档没有付费等待的人，这一号才用来升级更低档。付了更高档的人即使低档先有号，也不派低档医生。

不得虚构医生，不得在队列为空时显示已匹配、已同步。

## 同步内容

同步给医生端的订单至少包括：咨询卡片（咨询人、科室、问题描述）、所选档位、服务形态、接诊时限、退款规则、只升不降且不跨池的派单策略。接诊医生由医生端回填。身份信息按 [数据与大模型调用合规规范](../合规/医疗健康数据与大模型调用合规规范.md) 最小化传递，默认不经过模型。

医生端接收成功后返回对端订单号。本 agent 保存该号，用于对账和幂等，不再根据它推进问诊。同一问诊订单重复同步时，医生端不得生成第二单。
