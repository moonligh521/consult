# V0.1 应用结构

本文件规定第一批可运行代码的构建、包和测试落点。行为以 [一轮咨询](../product/V0.1一轮咨询.md) 为准。这里不引入 Redis、消息队列、向量库、MySQL 和 LangChain4j。

## 构建

Maven 坐标：

| 项 | 值 |
| --- | --- |
| groupId | `com.moonligh` |
| artifactId | `registration-assistant` |
| version | `0.1.0-SNAPSHOT` |
| Java | 21 |
| 父项目 | `spring-boot-starter-parent` `4.1.1` |

依赖只有这三项：

- `spring-boot-starter-web`：提供启动入口和 `/api/consultations` 接口
- `spring-boot-starter-validation`：校验修改卡片的字段
- `spring-boot-starter-test`：运行验收测试，作用域为 test

`src/main/resources/application.properties` 只放应用名和端口：

```properties
spring.application.name=registration-assistant
server.port=8080
```

不放地址、账号、密钥和数据源。

合并请求增加 `.github/workflows/verify.yml`。工作流在 `ubuntu-latest` 上执行 `mvn -B verify`，检查名是 `verify`。分支名检查仍由现有的 `branch-name` 工作流负责。

## 包

```text
com.moonligh.registration
├── RegistrationApplication
├── consultation
│   ├── ConsultationService
│   ├── InMemoryConsultationStore
│   ├── SlotParser
│   ├── SafetyGate
│   ├── SymptomExtractor
│   └── DepartmentRouter
└── api
    ├── ConsultationController
    └── ConsultationExceptionHandler
```

`consultation` 包承担槽位、急症分流、症状、科室和会话。`SafetyGate` 先于 `SlotParser` 的追问和 `DepartmentRouter` 的科室推荐。它只识别交付基线列出的四个短语，命中后服务状态定为 `URGENT`。`DepartmentRouter` 不能把 `URGENT` 改回普通导诊。会话存在 `InMemoryConsultationStore` 的进程内映射中。验收测试调用 `ConsultationService`，不通过 HTTP。

`api` 包把 [一轮咨询](../product/V0.1一轮咨询.md) 的路径、JSON 字段和错误码翻译成对 `ConsultationService` 的调用。控制器不写规则。

本版不创建 `infrastructure` 包。

## 服务方法

`ConsultationService` 对上层提供三个方法：

- `acceptMessage(consultationId, text)`：`consultationId` 为空则新建咨询
- `updateCard(consultationId, patch)`：按契约修改卡片
- `confirm(consultationId)`：确认当前卡片

返回值包含 `consultationId`、`status`、`prompt`、`missingSlot` 和 `card`。失败使用契约里的 `code`，由 `ConsultationExceptionHandler` 写成对应的 HTTP 状态和 `message`。

## 测试

`ConsultationAcceptanceTest` 覆盖 AC-1 到 AC-8，以及基线里 AC-2、AC-3 补齐缺失槽位后生成卡片。AC-4 之后的文本、修改和确认保持急症分流。断言使用契约里的状态、提示原文、症状数组和科室名。

另有一个控制器测试，用 AC-1 的请求确认 JSON 字段名与 HTTP 200 一致。错误码用 `CONSULTATION_NOT_FOUND` 确认 HTTP 404 和正文原文。

这些测试不启动 Redis、数据库或消息队列。
