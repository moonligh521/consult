# 真实医疗场景覆盖与审核规范

版本：2026.10.29

## 1. 覆盖率口径

总行数不是覆盖率。报告必须同时给出：

1. **目录覆盖率**：137 个已开通二级科中，有独立有效金标的比例。
2. **急症类别覆盖率**：12 个急症临床大类中，满足表达矩阵最小独立意图数的比例。
3. **人群覆盖率**：婴幼儿、儿童、青少年、18–39、40–59、60–79、80 岁以上七层中，有有效样本的比例。
4. **表达覆盖率**：标准语、口语、方言、错字、拼音、英文、ASR、否定、家属代述、多轮、混写十一类。
5. **复杂病例覆盖率**：单病不典型、多病同科、多病跨科、既往史干扰、药物不良反应、慢病急性加重、术后/产后、无症状检查异常等。

加权口径定义在 `coverage-taxonomy.json`。只有同时包含不少于 500 条有效双人临床金标和合规去标识真实流量时，才允许把加权结果标为正式覆盖率；否则只能写“专家先验估算”。

### 1.1 工程覆盖与正式临床覆盖

`coverage-quota.json` 定义的是 20 万条工程测试包的组装预算，不是临床有效性的证明。每条工程样本必须且只能归入一个主配额：`catalog_routine`、`safety`、`population`、`expression`、`complex_multiturn`、`state_machine` 或 `capacity`。前六类可在满足去重、独立意图和审核条件后参与工程覆盖统计；`capacity` 只验证吞吐、稳定性和数据管道，始终设置 `coverage_eligible=false`，不得进入覆盖率分子。

工程覆盖回答“约定的目录、风险、人群、表达、复杂度和状态路径是否被测试触达”。它可以使用规则复刻或合成候选，用于回归和发现缺口，但报告必须标记为工程覆盖或专家先验估算。正式临床覆盖回答“经临床审核且具备真实流量代表性的独立医学意图覆盖到什么程度”，必须满足双人盲审、分歧裁决、去标识真实流量、独立意图去重和发布门禁；工程样本数量再大也不能替代这些条件。

配额只限定 20 万条工程包的构成。最低独立意图、交叉单元目标和禁止失衡规则由 `coverage-taxonomy.json` 约束；复制、模板换皮或容量补齐不能用于达标。`quota_model.py` 在组装前校验总量、配额比例、主配额唯一性、最低目标和 `capacity` 的覆盖资格，但不生成场景，也不执行 20 万条组装。

工程状态只有在维度、交叉单元、精确配额和禁止失衡规则同时通过时才是
`COMPLETE`。失衡规则使用对应主配额作为分母，避免状态机重复或其他交叉层污染
科室、人群和表达族占比；全包分布只作观察。即便工程状态完成，也必须阻止把工程
矩阵 100% 解读成真实患者覆盖 100%，正式比例仍要由临床金标和真实流量给出。

仓库中的 `triage-cases.csv` 为固定 200,000 行工程包。除 `capacity` 外不得出现意外的
`input + prior_input + action` 精确重复；多轮样本必须保留完整 `prior_input` 链。
`capacity` 可复用业务行做吞吐验证，但必须单独归类并排除出所有覆盖率、Top1 和
临床证据分母。

**工程矩阵 100% 不等于真实患者覆盖 100%。** 前者只说明预定义分类单元和配额
已触达；它既不证明真实流量具有代表性，也不证明未建模疾病、罕见表达和人群已
覆盖。任何报告都不得把“工程覆盖 100%”改写为“真实患者覆盖 100%”。

## 2. 去重与有效样本量

- `intent_id` 表示医学意图；删除年龄、性别和病程包装后，同一意图只计一次。
- `scenario_id` 由意图、人群、性别和表达族共同确定。
- `normalized_hash` 用于发现文本近重复。
- 同一 `intent_id + expression_family` 簇无论复制多少行，只贡献一个有效样本。
- 原始行数、唯一文本数、唯一意图数、唯一场景数和有效样本量必须分别报告。
- `--pad-to` 只用于容量测试，补出的数据不得提高覆盖率。

## 3. 急症候选矩阵

`clinical_scenarios.py` 提供 12 类、每类 10 个表达族的候选矩阵。矩阵覆盖典型、口语、方言、错字、拼音、ASR、否定或已缓解、家属代述、多轮新增和中英数字混写。

这些样本的 `review_status` 是 `REVIEW_REQUIRED`，不是临床金标。它们可以暴露现行规则的盲区，但不得直接推动 `urgent-catalog.json` 中 DRAFT 规则升级。

## 4. 特殊人群

年龄按七层报告，不按默认“女，32 岁”模板计算覆盖。普通场景应兼有男性和女性；妇产、男科等只生成医学上适用的组合。年龄或性别不影响处置时，变化只能用于鲁棒性测试，不能制造新的临床意图。

40–59 岁、80 岁以上、孕产、儿童、认知或表达受限人群需要独立报告。明显不可能的年龄/性别组合标记 `synthetic_mapping_only=1`，不得进入准确率分母。

## 5. 多病与不典型病例

复杂病例使用 3–6 轮时间线，并标注：

- `acceptable_specialties`：可接受科室集合；
- `forbidden_specialties`：严重错误科室；
- `required_questions`：作出处置前必须追问的信息；
- `key_evidence`：参考结论依赖的原话；
- `prohibited_outputs`：不得输出的诊断、排除急症或治疗承诺。

复杂病例不强迫只有一个 Top1。评测同时报告 Top1、Top3、可接受集合命中率和严重跨科错误率。

## 6. 临床金标流程

运行下列命令生成候选审核包。输出名以下划线开头，命中仓库的 `_*.csv` 忽略规则：

```powershell
$env:PYTHONIOENCODING='utf-8'
cd docs/测试/全链路
python -c "from pathlib import Path; from clinical_gold import write_review_pack; write_review_pack(Path('_clinical-review-pack.csv'))"
```

审核要求：

1. 两名临床审核人独立盲审。
2. 两人不一致时由第三人裁决。
3. 记录审核人、日期、两份原始标签、裁决人和最终标签。
4. 计算 Cohen’s kappa；低于门禁值的集合不得用于发布验收。
5. 只有 `annotator=clinician` 且 `review_status=REVIEWED/ADJUDICATED`、字段校验完整的行才是有效临床金标。

规则复刻器产生的 `annotator=replica` 只用于代码回归，不是临床真值。

## 7. 真实流量

真实咨询进入评测前必须完成告知、审批和个人信息保护影响评估。`prepare_real_traffic.py`：

- 删除姓名、手机号、身份证号、院内号、地址和邮箱；
- 对主体 ID 使用环境密钥做 HMAC，不记录密钥；
- 年龄只保留年龄层，时间只保留月份；
- 按主体首次出现时间切分，同一主体不能跨 train、validation、hidden；
- 发现直接标识残留时拒绝写出。

```powershell
$env:REAL_TRAFFIC_HMAC_SECRET='<从密钥管理系统注入>'
python prepare_real_traffic.py real-traffic-raw-local.csv real-traffic-deidentified-local.csv
```

原始文件、去标识输出和密钥不得提交到 Git。上述真实流量文件名以及 `_*.csv`、
`triage-cases.csv` 已由 `.gitignore` 排除；禁止用 `git add -f` 绕过。

## 8. 发布指标

安全指标单独门禁：

- 高风险漏识别率；
- 危险性低估率；
- 错误预约拦截率；
- 多轮病情变化响应率。

所有比例同时报告样本数和 95% Wilson 置信区间。门禁使用置信区间的保守端：失败率看上界，成功率看下界。总体准确率不能抵消任何急症门禁失败。

`release-gates.json` 当前是待签署草案。医疗负责人和产品安全负责人未签署前，评测结果必须显示未通过治理门禁。

每次报告记录：

- 代码提交；
- 科室目录版本；
- 急症目录版本；
- 覆盖本体版本；
- 表达词典版本；
- 临床金标版本；
- 真实流量时间范围；
- 模型与提示词版本；
- 审核人与签署状态。

正式临床覆盖不追求固定 20 万行；20 万仅是工程测试包的容量契约。新增覆盖数据必须回答“增加了哪个独立临床意图、表达族或人群单元”，否则只能归入容量压测数据。
