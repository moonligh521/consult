# 技术设计

设计日期：2026-10-21。

本文是导诊挂号 agent 的实现依据。产品路径见 [项目目标](../产品/项目目标.md) 与 [问诊订单与医生派单](../产品/问诊订单与医生派单.md)。V0.1 的接口和类落点见 [一轮咨询](../产品/V0.1一轮咨询.md) 与 [V0.1 应用结构](V0.1应用结构.md)。测评见 [测评方案](测评方案.md)。

本仓库不实现医生接诊界面。问诊订单成功交给医生端之后，接诊、会话、诊断和处方在医生端完成。

## 结论

系统拆成两段：

1. **本 agent**：急症分流、多轮补槽、科室候选、咨询卡片；后续版本核验复诊、收款、创建问诊订单，把卡片、档位和派单策略同步到医生端。
2. **医生端**：按同步来的策略接诊、超时换人、只升不降地排队。诊疗过程不回到本 agent。

同步以医生端明确接收为成功。失败不得对患者显示已交给医生。接收成功后，本 agent 不再改派、不再催诊。退款和对账可以接收医生端回执，这不是继续问诊。

## Agent 数量与模式

本仓库一共 **2 个 Agent**。医生端不是本仓库的 Agent。

| Agent | 何时在线 | 职责 |
| --- | --- | --- |
| 导诊 Agent | 服务患者 | 分流、追问、科室卡片；后续版本收款并同步问诊订单 |
| 测评 Agent | 只在离线评测时运行 | 跑测试集、算出安全指标、写出是否允许扩大使用范围 |

模式是 **一个编排器调用多工具**，不是多个 Agent 互相商量，也不是模型自己决定下一跳的自由 ReAct。编排器是 `ConsultationService` 状态机。模型只作为「抽槽位、抽症状」这一个工具，抽完必须再过规则工具。规则工具的结论优先于模型。

```text
患者一句话
    → 导诊 Agent（状态机编排，不是 LLM 循环）
        → 工具 SafetyGate      规则，可一票否决
        → 工具 SlotParser / IllnessExtractor   V0.1 规则；后续模型只抽字段
        → 工具 SymptomExtractor
        → 工具 DepartmentRouter  规则，不能覆盖 URGENT
        → （后续）工具 FollowUpVerifier、Payment、OrderSync
    → 卡片或 URGENT 提示
    → 支付成功则 OrderSync；医生端接诊，导诊 Agent 结束

测评 Agent（离线）
    → 对测试集每一条调用同一套导诊 Agent
    → 对照参考答案计分
    → 输出漏识别率等，不给患者回话
```

V0.1 导诊 Agent 不接大模型，四个工具全是规则。接入 LangChain4j 之后仍是这一个导诊 Agent，只是把 `IllnessExtractor` 换成模型工具，编排顺序不变。

禁止的模式：多个诊疗 Agent 会诊、用一段系统提示词代替状态机、让模型选择跳过 `SafetyGate`、测评 Agent 直接对真实患者说话。

### 工具清单

导诊 Agent 的工具：

| 工具 | 实现 | 可被模型覆盖 |
| --- | --- | --- |
| `SafetyGate` | 规则 | 否 |
| `SlotParser` | V0.1 规则；后续可由 `IllnessExtractor` 补齐后再校验 | 否，校验失败继续追问 |
| `SymptomExtractor` | 短语表，后续模型只提供候选 | 否 |
| `DepartmentRouter` | 关键词表 | 否 |
| `FollowUpVerifier` | 后续，病历核验 | 否 |
| `Payment` | 后续，四档收银台 | 否 |
| `OrderSync` | 后续，同步医生端 | 否 |

测评 Agent 的工具：测试集读取、调用导诊 Agent 的同一套服务方法、对照参考标签、汇总指标、写出报告。不调用 `Payment`、`OrderSync` 的真实医生端。

### 用不用 loop

| 场景 | 用不用 | 怎么用 |
| --- | --- | --- |
| 患者多轮追问 | 用 **状态机循环** | 一次只追问一个槽位，急症立即停。不是模型 while 调工具 |
| 导诊推理 | **不用** LLM ReAct / 自主 loop | 每轮请求走固定工具顺序，跑完即返回 |
| 测评跑测试集 | 用 **有界 for 循环** | 一条用例一次调用，集合跑完停止 |
| 模型或规则升级后回归 | 用 **整轮重跑** | CI 或手工再跑测评 Agent 一遍，不是挂在患者路径上 |
| 线上定时巡检 | V0.1 **不用** | 后续若要定时回归，用 CI 定时任务跑测评批；不用 Cursor `/loop` 服务患者 |

导诊 Agent 没有开放步数的工具循环。测评 Agent 的循环上限等于测试集条数。Cursor 的 `/loop` 只适合开发时催促本地 `mvn verify`，不进入生产编排。

## 安装与运行

V0.1 本地只需 JDK 21 和 Maven。不安装 Redis、RocketMQ、MySQL、向量库和模型密钥。

```text
JDK 21
Maven 3.9 或以上
mvn -B verify
mvn -B spring-boot:run
```

服务端口 `8080`。`application.properties` 只放应用名和端口。密钥、医生端地址和数据源不进仓库，后续版本用环境变量注入。

后续版本每引入一项能力，按 [基础设施](基础设施.md) 同时补依赖、端口和封装。典型安装顺序：JDK 与本应用 → MySQL 8.0.46（问诊订单落库）→ Redis 8.2.10（派单锁与缓存）→ RocketMQ 5.5.1（同步事务消息）→ LangChain4j 与 DeepSeek（抽槽，密钥在环境变量）。医生端是外部系统，本仓库只配置它的接收地址和鉴权。

合并请求在 GitHub Actions 跑 `branch-name` 与 `verify`（`mvn -B verify`）。

## 六层怎么落地

| 层 | 本仓库怎么做 | 医生端 |
| --- | --- | --- |
| 1 入口与告知 | 声明服务身份；采集身份前单独告知。V0.1 不做登录 | 医师账号与执业校验 |
| 2 安全分流 | `SafetyGate` 独立于模型。不可用时不建单、不同步 | 接收后仍可按院内规则拒绝急症单 |
| 3 导诊整理 | 状态机补槽、抽症状、规则推荐科室。模型只抽槽位和症状 | 使用同步过去的卡片，不让模型在本侧继续诊疗 |
| 4 医院科室与档位 | 确认咨询卡片后进入四档下单页 | 按档位供给池接诊 |
| 5 订单同步 | 创建问诊订单，同步医生端，幂等，失败不假成功 | 返回对端订单号；接诊后状态以医生端为准 |
| 6 审计测评 | 记录状态、规则版本、同步结果。测评见 [测评方案](测评方案.md) | 诊疗病历按互联网诊疗规则保存 |

## V0.1 切片

本版只实现第 2 层四个短语和第 3 层槽位、科室、卡片。进程内存会话。包和测试以 [V0.1 应用结构](V0.1应用结构.md) 为准。

请求进入 `ConsultationController`，规则在 `ConsultationService`。顺序固定为：`SafetyGate` → `SlotParser` → `SymptomExtractor` → `DepartmentRouter`。命中急症后状态为 `URGENT`，后面的科室规则不得改回普通导诊。

不创建 `infrastructure` 包，不调用医生端。

## 问诊订单（后续版本）

咨询卡片确认、患者选定四档之一并支付成功后，立即创建问诊订单并同步医生端。急症分流触发则不进入下单页。档位编码、服务形态和退款时限见 [问诊订单与医生派单](../产品/问诊订单与医生派单.md)。

同步给医生端的字段：

| 字段 | 用途 |
| --- | --- |
| `consultationId` | 本 agent 咨询编号 |
| `orderId` | 本 agent 问诊订单号，同步幂等键 |
| `card` | 咨询人、科室、问题描述、症状 |
| `paidTier` | `GENERAL` 普通咨询、`RAPID` 极速咨询、`TERTIARY` 三甲医生、`EXPERT` 权威专家 |
| `sla` | 时长、轮次、接诊后未回复退款时限 |
| `dispatchPolicy` | 公立池只升不降；极速自营池不跨池；同档先到先得 |
| `queueState` | 待同步 / 已接收。接诊医生由医生端回填 |
| `followUpVerified` | 复诊核验结果。互联网诊疗复诊单未通过则不同步 |
| `safetyStatus` | 未触发急症才能同步 |

医生端接收成功后返回 `externalOrderId`。本 agent 保存该号，用于对账和幂等，不再用它推进问诊。同一 `orderId` 重复同步，医生端不得生成第二单。

医生超时未接、换人、升档、排队，都在医生端按 `dispatchPolicy` 执行。本 agent 不在同步后再改这些字段，除非医生端回传「未接诊、需退款」。

实现时增加端口，名称在首次编码时写入 [基础设施](基础设施.md)：

- 问诊订单仓储（MySQL）
- 医生端同步（HTTP 或消息，失败可重试，超时不得记为成功）
- 同步事务消息（RocketMQ，唯一流水号等于 `orderId`）
- 并发锁（Redis，避免同一支付结果写出两单）

业务代码只依赖这些端口。医生端客户端类型留在 `infrastructure`。

## 失败处理

| 情况 | 行为 |
| --- | --- |
| 安全引擎不可用 | 不视为低风险，不生成卡片，不创建问诊订单 |
| 模型超时或无把握 | 不编造科室或医生。V0.1 无模型，规则单独可测 |
| 复诊核验失败 | 可保留科室推荐；不创建问诊订单 |
| 医生端同步超时或失败 | 可重试；患者侧不显示已交给医生 |
| 医生端回传未接诊 | 本 agent 只做退款和对账，不重开诊疗对话 |
| 号源或医师目录不可用 | 不显示已匹配、已同步 |

## 数据与模型

症状按敏感个人信息处理。身份证号、手机号尽量只在创建订单和同步医生端时出现，默认不进入模型，也不写入普通日志。病历和检查报告默认不上传。处理角色、保存期限和跨境限制见 [医疗健康数据与大模型调用合规规范](../合规/医疗健康数据与大模型调用合规规范.md)。

LangChain4j 调用 DeepSeek 时，抽取结果必须再过 `SafetyGate` 和科室规则。提示词不能授予「忽略安全规则」的权限。
