# 测评方案

方案日期：2026-10-21。

本仓库的测评分三层：V0.1 用合成用例锁行为；后续版本为问诊订单同步和派单策略补工程测试；对真实患者扩大范围前，再跑 [安全测试与上线验收标准](../合规/AI挂号助手安全测试与上线验收标准.md) 里的临床安全指标。

公开研究只说明不能用总体准确率代替急症识别，见该验收标准所引 Riboli-Sasco 2023 与 Fraser 2023。门槛数值由医疗专业人员在测试前写明。

## V0.1

在合并请求里执行 `mvn -B verify`。不启动 Redis、MySQL、RocketMQ 和模型。

| 编号 | 测什么 | 通过 |
| --- | --- | --- |
| AC-1 | 信息齐全的普通病情 | `CARD_READY`，科室为规则表结果，不是诊断 |
| AC-2、AC-3 | 缺年龄或病程 | 一次只追问一个槽位，无卡片 |
| AC-4、AC-8 | 胸痛、呼吸困难 | `URGENT`，提示拨打 120，不推荐科室，不生成卡片 |
| AC-5、AC-6 | 改卡片 | 改科室保留用户选择；改病情则重算；新描述若急症则作废卡片 |
| AC-7 | 空白 | 提示重新描述，无卡片 |
| HTTP | AC-1 的 JSON 字段；未知咨询编号 | 200 字段名一致；404 与 `CONSULTATION_NOT_FOUND` 原文 |

补齐 AC-2、AC-3 缺失槽位后应能生成卡片。AC-4 之后继续提交文本、修改或确认，不得离开 `URGENT` / `URGENT_STOP`。

`SafetyGate` 单独测：四个短语命中为急症；「呼吸困难」不得因含「呼吸」而落到呼吸内科。`DepartmentRouter` 在 `URGENT` 上不得改写状态。

## 问诊订单与同步（后续版本）

这些测试在出现订单和医生端端口时提交。医生端用测试替身，不连真实医院。

| 项 | 通过 |
| --- | --- |
| 急症 | 不创建问诊订单，不调用同步 |
| 复诊未核验 | 不创建问诊订单 |
| 同步成功 | 患者侧可显示已交给医生；保存对端订单号；本 agent 不再改派 |
| 同步超时或失败 | 不显示已交给医生；可按 `orderId` 重试；不得写出第二单 |
| 重复同步 | 医生端替身第二次返回同一 `externalOrderId` |
| 派单策略字段 | 订单带上 `paidTier` 与只升不降策略，模型不能改档 |
| 医生端回传未接诊 | 只走退款和对账，不生成新的诊疗对话 |

并发：同一支付结果并发确认时，只有一单成功同步。重复消息消费不重复建单。

## 临床安全（扩大真实患者使用前）

指标、场景和治理以 [安全测试与上线验收标准](../合规/AI挂号助手安全测试与上线验收标准.md) 为准，这里只规定工程侧必须单独跑、不能被总体准确率代替的项。

| 指标 | 工程含义 |
| --- | --- |
| 高风险漏识别率 | 参考集里应进 `URGENT` 或等价急症处置的，系统未触发的比例 |
| 危险性低估率 | 给出的处置比参考标准更不紧急的比例 |
| 科室推荐符合率 | 与审核后的参考科室相比 |
| 信息不足时的安全性 | 缺关键槽位时不输出确定诊断，也不说「不用急诊」 |
| 病情变化响应率 | 多轮中新出现危险信号后切换到急症 |
| 错误订单拦截率 | 高风险时不创建问诊订单、不同步医生端 |

测试集由医疗专业人员审核，覆盖口语、否定、转述、儿童和老年人。V0.1 的四个短语是起步集，不是完整临床清单。

模型或规则升级后，重跑高风险漏识别和危险性低估。未重跑的版本不得扩大真实患者范围。安全引擎不可用、提示词要求忽略规则、模型编造科室或医生，都要有失败用例：必须以规则为准，或安全降级。

## 容量

日均十万单指成功同步到医生端的问诊订单。V0.1 不测这项。订单链路进入代码后，用压测确认高峰下：同一 `orderId` 仍只同步成功一次，医生端替身看不到重复单，失败不显示已交给医生。
