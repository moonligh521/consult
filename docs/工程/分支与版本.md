# 分支与版本

版本分支使用 `feature-V主.次-年月日`。`feature-V1.3-20260720` 表示 V1.3 的开发分支，创建日期是 2026-07-20。

日期使用中国时区的创建日，写成 8 位数字。版本号遵循语义化版本，分支和标签里的 `V` 大写。

## 分支

| 种类 | 名称 | 从哪里拉出 | 合回哪里 | 用途 |
| --- | --- | --- | --- | --- |
| 发布线 | `main` | — | — | 只保留已发布或即将发布的提交。合并后打标签 |
| 版本开发 | `feature-V主.次-年月日` | `main` | 经发布分支合入 `main` | 一个计划版本只有一条。当前是 `feature-V0.1-20261021` |
| 并行任务 | `feature-V主.次-年月日-短英文名` | 对应版本开发分支 | 对应版本开发分支 | 同一版本需要并行改动时使用。短英文名只用小写字母、数字和连字符 |
| 发布冻结 | `release-V主.次-年月日` | 对应版本开发分支 | `main`，并合回该版本开发分支 | 只接收该版本的缺陷修复。日期是冻结日 |
| 线上修复 | `hotfix-V主.次.修订-年月日` | `main` 上已发布标签 | `main`，并合入当时仍在开发的版本分支 | 修复已经发布的版本。标签使用完整的修订号 |

`main` 不直接接收功能提交。版本开发分支不合入下一条版本开发分支；下一条版本从打过标签的 `main` 拉出。

已经发布的版本不复用旧分支名。放弃的分支删除前先确认没有未合并的提交。

## 名称示例

符合规范：

```text
feature-V0.1-20261021
feature-V1.3-20260720
feature-V0.1-20261021-consultation-card
release-V0.1-20261130
hotfix-V0.1.1-20261202
```

不符合规范：

```text
feat/consultation-card
feature/V0.1
feature-V0.1.0-20261021
feature-v0.1-20261021
Feature-V0.1-20261021
```

版本开发分支和发布分支不写修订号。修订号只出现在线上修复分支和标签里。

## 标签

标签打在 `main` 上，使用注释标签。

| 标签 | 时机 |
| --- | --- |
| `V0.1.0` | V0.1 首次发布 |
| `V0.1.1` | 已发布 V0.1 的缺陷修复 |
| `V0.2.0` | 下一个包含新能力的版本 |
| `V1.0.0` | 对外承诺兼容的第一个正式版本 |

发布前把 `CHANGELOG.md` 的 `Unreleased` 归入对应标签。骨架阶段不打标签。

## 合并

1. 并行任务分支通过合并请求进入 `feature-V主.次-年月日`。
2. 版本达到 [V0.1 交付基线](../产品/V0.1交付基线.md) 的完成定义后，拉出 `release-V主.次-冻结日`。
3. 发布分支通过合并请求进入 `main`。
4. 在 `main` 的合并提交上打标签。
5. 把发布分支合回原来的版本开发分支，避免冻结期间的修复丢失。
6. 下一条版本从新标签拉出，例如 `feature-V0.2-20261215`。

只有一名开发者、且还没有需要冻结的缺陷时，版本开发分支也可以直接通过合并请求进入 `main`，然后打标签。进入 `main` 之前仍然要满足该版本的完成定义。

## 提交

提交说明统一使用中文。类型和说明都用中文，中间用中文冒号，句末加句号：

```text
功能: 补充科室规则的关键词表。
修复: 修正缺年龄时仍生成卡片的问题。
文档: 冻结 V0.1 交付基线。
测试: 补上空白输入的验收用例。
```

标题用动词开头，说清这次提交做了什么。说明里不再使用英文类型前缀。类型使用：功能、修复、文档、测试、重构、构建、杂务。

## 仓库保护

这些规则写给远端仓库。分支推送到 `origin` 之后，由维护者在 GitHub 上按下面的设置启用保护。启用前，远端分支尚未受到这些限制。

`main`：

- 禁止直接推送，禁止强制推送，禁止删除分支
- 合并必须经过合并请求，头分支必须是版本开发分支、发布分支或线上修复分支
- 必需状态检查为 `branch-name`
- `verify` 工作流进入仓库之后，把 `verify` 加为必需状态检查
- 必需审批人数为 0。仓库仍由一名维护者开发，合并请求用来跑检查。出现第二名维护者后，把必需审批改为 1，并勾选过期审批作废

`feature-V0.1-20261021` 以及以后的版本开发分支：

- 禁止强制推送，禁止删除分支
- 并行任务分支合入版本开发分支时，必须经过合并请求
- 必需状态检查与 `main` 相同
- 允许维护者把该版本的提交直接推到这条版本开发分支

本地可以先执行：

```bash
bash .github/scripts/check-branch-name.sh feature-V0.1-20261021
```
